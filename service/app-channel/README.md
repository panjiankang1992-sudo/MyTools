# MyTools 应用内通道

手机在个人页面启用“应用内通道”后，按以下顺序选择业务传输。家庭局域网优先；外网通道使用当前账号的正常 JWT，不创建系统 VPN，也不修改系统 DNS、代理或路由。

1. 已通过服务身份验证的家庭 LAN。
2. 本轮发现已验证的家庭 IPv6 入口，通过 WSS 建立应用内直连通道。
3. 与当前账号绑定的公网 HTTPS 服务来源完全相同的 WSS 中继，即 `origin === serviceOrigin`。此候选不要求 IPv6 可用，也不能由其他域名或相似前缀替代。
4. 通道候选均未通过时，恢复原有公网 HTTPS 业务入口。

每个通道候选先通过固定入口的正常 `ProfileApi` 身份请求，再经本进程随机能力路径流式读取 `/api/app/v1/connectivity/transport-probe`。探针必须在 2,500 毫秒内收到 HTTP 200、`Content-Length: 524288`、`Cache-Control: no-store` 及完整 512 KiB，逐字节核对 `byte[i] === i % 256`。不接受重定向或压缩内容，不保存正文，不使用代理或缓存。这个质量门槛从探针调用开始计时，不能用握手成功、首字节或部分响应替代。

身份和质量均通过后才激活能力路径。直连通道显示“应用内通道”，公网通道显示“公网中继”；候选连接中继续使用原有业务入口。直连候选的握手、身份和质量合计最多五秒，公网候选最多十秒，一轮通道选择最多十五秒；发现服务另有既有截止时间。公网冷 TLS 握手的预算与 2.5 秒质量门槛分开，通道选择不阻塞工具首屏渲染。

同一网络中失败的直连被记住；已通过质量验证的中继不会因下一轮重新发现 IPv6 而来回切换。LAN 仍可优先替换它。网络改变、开关重启或用户在连接设置中重新检测时清除质量结论。候选取消、账号/线路代次变化及迟到回调不能激活旧通道或关闭替代通道；未确认候选失败只回收候选资源。通道中断后的重试不重放写请求。现有登录、刷新和安全存储规则保持原样，网络故障不等于退出登录。

手机使用 TLS 套接字校验证书链，并按叶证书 SAN 核对域名，再发送带认证头的 WebSocket 升级请求。生产包使用系统信任根。

系统 IPv6 解析异常时，客户端沿用当前网络配置的 DNS 查询 AAAA。引导、公开挑战和身份校验三个固定控制接口直接使用已验证的 TLS 连接，其他直连 HTTPS 请求显式选择 IPv6。TCP 按本轮解析结果连接后升级 TLS，证书仍按原域名验证。DNS 与后续请求使用独立的截止时间。故障处理按请求的会话和线路代次隔离，避免旧请求清除新通道。

## 家庭端

服务使用 Python 3.12。安装 `requirements.txt` 中的依赖，在 `/etc/mytools-app-channel.env` 中设置 `MYTOOLS_CHANNEL_HOST` 为已有 IPv6 HTTPS 入口的证书域名。服务监听 `127.0.0.1:23483`，通过 `127.0.0.1:23200` 验证登录，把业务请求转到 `[::1]:8443`，使用固定域名校验 TLS 证书并匹配原有 Nginx 虚拟主机。每笔请求沿用业务接口自身的鉴权。

`mytools-app-channel.service` 使用独立动态系统用户，访问范围限于回环地址。将 `nginx-location.conf` 仅包含在目标 HTTPS 虚拟主机中，执行 `nginx -t` 后 reload。已有网关和媒体服务可以独立运行。回退时移除该 include、验证并 reload Nginx，再停用该 systemd 服务。

公网中继在当前可信公网主机的 Cloudflare Tunnel ingress 中增加一条规则，放在该主机原业务匹配之前：精确正则 `^/_mytools/app-channel/v1$` 转到 `http://127.0.0.1:23483`。其余业务路径继续沿用原规则和相对顺序；不把 `/api/`、健康检查或任意前缀整体公开到通道服务。规则应先通过配置校验和匹配测试，再由当前实际托管 cloudflared 的服务应用；不要假定它一定运行于系统级 systemd。此处描述配置要求，部署和公网端到端验收状态应以当次发布记录为准。

## 传输与验收

手机回环入口使用临时端口和每次连接随机生成的能力路径。最多复用五条 WSS 连接，每条同时承载一笔 HTTP 交换。媒体批量传输及精确的 `GET`/`HEAD /api/app/v1/reader/sources` 最多共占四条，给控制接口保留容量。排队取消立即释放；等待超过十五秒的未转发请求返回完整的 503 响应，不重放写请求，也不将局部拥塞当作整个通道失效。

服务端允许固定的 `/api/` 业务路径，保留 Range、Content-Range、长度和编码等头部，按窗口等待手机确认，实现有界流式传输。每个 1 MiB 窗口发送 `FLUSH` 并最多等待四十秒的文本 `ACK`；完整响应发送 `END` 后最多等待三十秒的文本 `ACK`。连接寿命九百秒只限制开始新请求，已开始的响应完整结束后再换连接；原有空闲和读操作超时继续生效。

固定质量探针只在已通过 JWT 验证的 WSS 内响应，不访问业务上游，不返回账号或媒体数据。公网精确入口接受经过认证的 WebSocket 升级，普通 HTTPS 请求不提供该下载探针。`probeRequests` 记录服务端执行次数；客户端仍须按时收到完整 512 KiB 并逐字节验证，服务端写入完成不能替代质量准入。普通业务请求仍逐笔执行原有接口鉴权；通道不是登录期限或授权范围的替代品。

大视频起播前会比较通道与公网对同一票据的完整 256 KiB 区间读取。通道视频同样具有首播截止和停滞检查，备用读取验证成功后只切换当前视频，保留播放进度与播放意图。单段视频失败不拆除其他业务接口的健康通道。视频画面上方的常驻触摸层负责重新唤出隐藏控件。

本地执行 `python3 -W error -m unittest -q test_channel` 可检查握手、原有授权边界、路径校验、连接复用、上传和分段读取。家庭端可读取 `http://127.0.0.1:23483/health` 的计数。手机需同时验证头像旁的模式、图库、视频开始播放和拖动后继续播放，并对照 completed、images、video 或 ranges 的增量。测速应使用同一手机、网络和同一份媒体。

健康状态中的 `responseStatus`、`requestMetrics` 和 `failures` 仅统计状态码、请求数、字节、耗时和固定失败类别，不保存请求路径、用户信息或认证材料。模拟器的合成媒体回归用于检查协议和播放器；真实家庭 IPv6 的可达性与吞吐需要独立实测，不能用公网回退或本地测试替代。

512 KiB 质量探针通过只表明本次候选达到准入条件，不代表真实大列表、图库或视频已经提速。公网中继需继续用真实账号验证完整书源列表、图片和 Range 起播/拖动，并记录实际徽标、完成字节、超时和失败计数。
