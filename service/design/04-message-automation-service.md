# Message Automation Service 详细设计

## 职责

消费标准化入站消息，匹配规则，提取命令、链接和附件，创建下载或其他业务任务，并请求 Messaging Service 回复结果。

## 数据模型

- `automation_rules`：渠道、会话、发送者、匹配条件、动作。
- `automation_runs`：输入消息、规则版本、业务结果。
- `action_bindings`：动作到任务定义的映射。
- `automation_outbox`。

## 执行流程

1. 消费 `MessageReceived` 并通过消息 ID 去重。
2. 匹配启用规则和授权范围。
3. 创建 `DownloadRequest` 或直接创建白名单任务。
4. 保存任务实例关联。
5. 消费任务状态事件并生成进度或完成通知。

## 脚本与子任务

复杂自动化可由入口脚本创建多个子任务，例如一个邮件包含多个链接时，父任务创建多个下载子任务，再创建汇总子任务。父任务应使用 `ALL_SUCCESS`、`ANY_SUCCESS` 或允许部分成功的聚合策略。

脚本只能创建 `action_bindings` 白名单内的任务，不能指定任意脚本或执行节点。

## 迁移

1. 从 DownloadBot 提取消息解析和下载触发规则。
2. 保留原 Bot 入口并镜像产生标准消息事件。
3. 对比新旧规则执行结果。
4. 切换创建任务入口，最后移除 DownloadBot 渠道耦合。

## 验收

- 重复消息不会重复创建下载任务。
- 未授权会话或发送者无法触发自动化。
- 多附件任务可以独立取消和汇总状态。
