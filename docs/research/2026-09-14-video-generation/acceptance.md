# 视频生成逐项验收矩阵

状态：待 P0 执行，以下全部为验收要求，不代表已通过。沿用图片验收原则：API 成功与视频效果分别判断，不挑选最好的一张代替全部结果。

## 功能与质量样例

每组至少 3 个不同主体 × 2 个固定种子（42、932），先 49 帧冒烟再 81 帧；完整模型模式需 6 个正式样例。通过后连续 10 个任务做稳定性补测。故障注入独立计数。

| ID | 模式 | 样例与目标 | 失败判据 |
|---|---|---|---|
| T01 | 文生 | 茶壶冒蒸汽、风中树叶、成年人挥手；固定主体/动作/运镜 | 静止复制帧、动作未发生、严重变形 |
| I01 | 单图首帧 | 从已有茶壶/湖景/人物图开始，轻微动作 | 开场构图主体完全不同，误当纯 R2V |
| R01 | 两图主体 | 茶壶＋杯子、人物＋背包、玩具＋背景 | 只采用一张，主体融合成错误物体 |
| R02 | 三图主体 | 主体、道具、场景分别输入，逐图标用途 | 忽略输入/同一角色变成多人；上传順序意外改变语义 |
| F01 | 首尾帧 | 同一物体位置/姿态变化；两端图有合理连续性 | 尾图被忽略、过渡全程硬切/闪烁 |
| S01 | 分镜 | 3 张图依次生成3镜头、逐镜提示词 | 顺序错、失败镜头被掩盖、转场时长错误 |
| V01 | 整体重绘 | 玩具运动视频改水彩；镜头和运动方向保留 | 原动作消失、仅抽一帧另生成、背景全不受控 |
| V02 | 控制信号 | 同一源视频对比灰度/边缘/深度 | 把原 RGB 冒充深度；过强结构限制导致未改编 |
| M01 | 局部修改 | 替换静止区域，再测试移动区域的跟踪蒙版 | 黑白蒙版反转、蒙版外明显漂移、漏改区域 |
| E01 | 纯指令编辑候选 | Kiwi：移除道具/换背景，保持主体动作 | 把所有内容重绘当作成功局部编辑 |
| A01 | 保留原声 | 裁剪后保留音轨、原无音轨、输出长度有偏差 | 音画时长错配、凭空标记有原声、静音策略失效 |
| P01 | 提示词建议 | 中文描述、空提示词＋素材、相互冲突指令 | 自动扩写改变用户保持项、未经确认上传外部 |

每条正式视频至少检查首/中/末关键帧并完整播放两遍。评分：指令遵循、主体保持、时间连贯、编辑局部性（适用时）、伪影，每项 1–5。拟定模式准入：至少 5/6 样例各关键项≥3，无严重主体替换/全黑/破损/忽略核心输入；其余明确标有限或不可用。评分是人工判断，自动相似度仅作辅助。

## 服务与故障验证

| ID | 项目 | 必须结果 |
|---|---|---|
| B01 | 跨账户输入/输出/历史 | 拒绝读写其他用户资产，包括衍生再创作 |
| B02 | 重复提交、同键异参 | 相同请求重放返回同任务；异参冲突；无重复 GPU 推理 |
| B03 | 排队取消/运行取消 | 排队即取消；运行确认资源释放后取消，无僵尸任务 |
| B04 | Worker 断开/重启 | reconciliation 查旧任务，不直接重新生成 |
| B05 | OOM/磁盘不足/非法文件 | 明确错误、无其他服务被杀；半成品不当成功发布 |
| B06 | 视频运行时图片/标签入队 | 不因旧 120 秒锁等待而失败；无同时占用 GPU |
| B07 | 视频结束后图片/标签恢复 | 各跑一个真实任务，确认模型切换正常 |
| B08 | 结果保存重试 | 生成不重复执行；资产登记幂等，可恢复 PUBLISHING |
| B09 | 超长/超大/损坏素材 | 探测阶段拒绝，不能先完整解码耗尽内存 |
| B10 | HTTP Range/真机播放 | 首帧可见、拖动可用、音画正确、下载和原声策略一致 |
| B11 | App 退出/切账号/网络恢复 | 任务不丢失，账户隔离，旧账号状态不串入新账号 |
| B12 | 回退 | 关闭新任务、排空、恢复旧版，不删除作品 |

## 性能目标与证据

不预先宣称多少秒生成完成。P0 每模式记录所有耗时与最大值；小样本不使用“稳定 P95”的措辞。积累至少 30 个真实样本后再报告 P50/P95，并区分冷/热与排队。

建议先将 5 秒片段的产品目标设为生成阶段中位数≤10分钟、尾部≤20分钟，30分钟硬上限；这是产品目标，不是硬件测量。如果做不到，界面明确慢速实验，或改用通过验收的快速候选，不暗降画质。

交付目录：

```text
verification/video-generation/<run-id>/
  manifest.json
  host-before.json
  cases.jsonl
  inputs/               # 验收素材及来源，不混入用户私有素材
  outputs/              # 原始视频，保留失败和有限通过样例
  metrics/              # GPU / memory / 时间
  reviews.json
  health-after.json
  report.md
```

manifest 固定 repo/权重/工作流版本；cases 记录有效输入映射；reviews 不只保存总分，要写实际缺陷。交付报告逐模式说明可用范围、性能和失败样例。
