# MyTools 图片风格配置调研与可用资源包

调研日期：2026-09-14。

后续进展：文字风格首版已完成本地开发，参见 [实现与使用说明](../../design/2026-09-14-image-style-implementation.md)。下文保留调研当时的状态与分阶段设计。

本次交付是**实现设计、已下载的开放模板资源、可立即合成提示词的离线工具，以及自定义操作方法**。未修改线上服务或 App；App 尚没有“风格库/我的风格”管理入口。模板可以通过现有提示词输入框使用；24 种精选模板尚未逐项进行 GPU 画质验收，不能将资源获取或格式校验等同于效果验收。

## 结论与实现分层

建议先上线“文字风格预设 + 账户私有自定义”，再增加 Krea 2 专用 LoRA 和图片风格参考。风格描述控制媒介、笔触、配色、光线；采样参数控制推理过程；两者分开管理。

| 方式 | 如何生效 | 对当前项目的改动 | 本次状态 |
|---|---|---|---|
| 文字风格 | 主体描述与风格模板合成正向提示词 | 风格目录、合成、快照、App 选择与管理 | 24 个模板和合成工具可用，App 接入待实现 |
| LoRA 风格 | 加载与 Krea 2 匹配的小型权重，并带入触发词 | 受管权重目录、模型加载节点、强度绑定、独立工作流验收 | 9 个官方候选的固定版本、URL、摘要已获取；权重未下载 |
| 图片风格参考 | 独立参考条件影响新图视觉风格 | 专用参考工作流、对应模型/LoRA、1–2 张图验收 | 官方路径已查明，现网仍不开放 |
| 图生图 | 底稿编码为潜变量后加噪重绘 | 已有独立工作流 | 已实现；不能作为独立风格参考能力的替代证明 |

Krea 2 与 FLUX.1 Krea 是不同模型系列，不能混用后者的 LoRA 或参数建议。官方建议 Krea 2 使用自然语言描述：[Krea 提示词指南](https://github.com/krea-ai/krea-2/blob/main/docs/prompting.md)。

## 本地代码核查

- `ImageModels.Create` 当前只有模型、prompt、mode、references、size、count、seed、idempotencyKey，没有 styleId、negativePrompt 或 denoise。
- `ImageService.create` 已持久化任务请求和工作流修订，可扩展为不可变的风格快照；不能执行时再读取最新风格。
- App `ImageGenerationPage.ets` 已有提示词回填、底稿和重试流程，但没有风格管理。
- 图生图候选文件 `krea2-image-edit-v1.candidate.json` 使用 8 steps、CFG=1、euler/simple、denoise=0.65，负向条件来自 ConditioningZeroOut。当前不支持用户负向提示词，也没有 LoRA 节点。
- `STYLE_REFERENCE` 是单独验收门禁。文字风格不应占用该模式名称。

## 已获取的开放资源

### 文字风格：twri/sdxl_prompt_styler

[上游仓库](https://github.com/twri/sdxl_prompt_styler)采用 JSON `{prompt}` 占位符模板，[许可证为 MIT](https://github.com/twri/sdxl_prompt_styler/blob/main/LICENSE)。已下载固定提交 `51068179927f79dce14f38c6b1984390ab242be2`，保存原始 JSON、README、许可证及每个文件的 SHA-256，见 [来源清单](resources/twri/provenance.json)。

原始库共 107 条：1 条 base、17 条 sai、89 条 twri，即 106 条非 base 模板。原始库作为来源留档，不直接全部作为 App 默认选项；精选 24 种通用风格，改写为自然语言，去除不适用于当前工作流的负向参数。每条都保存原始条目名称与文件位置，见 [内置风格包](builtin-styles.json)。原始模板源于 SDXL，改写后的 Krea 2 实际效果仍需对照图验收。

| 分类 | 首批内置风格（括号为配置 id） |
|---|---|
| 绘画 | 水彩 watercolor、印象派 impressionist、点彩 pointillism、超现实 surrealist |
| 设计 | 装饰艺术 art-deco、新艺术 art-nouveau、波普 pop-art、像素 pixel、等距 isometric、极简 minimalist |
| 插画 | 动漫 anime、漫画 comic、线稿 line-art、数字绘画 digital-art、奇幻 fantasy |
| 立体 | 低多边形 low-poly、黏土 clay |
| 纸艺 | 折纸 origami、多层剪纸 paper-cut |
| 摄影 | 黑白 monochrome、写实 photographic、胶片 analog-film、电影感 cinematic、美食 food-photo |

内置配置使用英文名称与键，中文展示名称由 App 资源文件维护。可保留“无风格”作为默认行为，直接传入用户原始提示词。

Fooocus 也是可参考的风格目录来源，但本轮选择许可明确、结构简单的 twri 作为实际导入来源；不依赖安装其 ComfyUI Python 插件，只使用静态模板数据。

### Krea 2 官方 LoRA 候选

[ComfyUI 官方 Krea 2 指南](https://docs.comfy.org/tutorials/image/krea/krea-2)列出专用风格、触发词和强度。已通过 [Comfy-Org/Krea-2](https://huggingface.co/Comfy-Org/Krea-2/tree/main/loras) 获取候选资源元数据，固定修订 `e5ea8b4dd7f38f348b138eb0fe29f92c0e367e96`。完整下载 URL、文件大小、SHA-256、触发词在 [LoRA 候选清单](krea-lora-candidates.json)。

9 种包括：墨刷、点描、儿童涂画、霓虹抽象、雨窗、复古动漫、柔和水彩、落日虚化、复古塔罗。官方推荐强度均为 1.0；这只是评估起点，不是本项目已验证范围。每个文件约 469 MB，9 个合计约 4.22 GB（十进制），本次只取目录与元数据，没有下载权重。

接入时将已校验文件置于受管 `models/loras/`，在基础模型输出与采样器之间加入兼容的 LoRA 加载节点；文件名和强度由服务端目录解析，触发词只合并一次。先用当前 NVFP4 模型评估加载兼容性、峰值显存与耗时，再决定是否需要单独 FP8 工作流。不得把“基础模型可运行”推断为“所有量化组合与 LoRA 均可运行”。

独立图片风格参考在官方方案中使用 INT8 Convrot 基础模型和 `krea2_style_reference.safetensors`，不能只把普通风格 LoRA 打开就视为完成。

模板 MIT 许可不覆盖 Krea 权重。权重遵循 [Krea 2 Community License](https://www.krea.ai/krea-2-licensing)，其中商业使用有收入门槛及其他条件；发行时保留对应模型协议和归属说明，不将其标为 MIT。

## 风格与生成参数怎么配置

| 配置 | 第一阶段产品行为 | 实现要点 |
|---|---|---|
| 风格 | 默认无风格，每次选一个内置或私有风格 | 单选避免多模板冲突；未来组合需明确顺序 |
| 风格描述 | 可预览、复制，复制内置后编辑 | 模板只允许一个 `{prompt}`，禁止执行表达式 |
| 配色、光线、材质 | 可在自定义描述中调整 | 保存为风格内容，不偷偷改动用户主体 |
| 尺寸、张数、种子 | 沿用当前模型能力目录 | 种子用于对比条件，不能跨模型/硬件保证逐像素复现 |
| 图生图重绘程度 | 当前仍固定 0.65 | 后续独立参数；候选 0.35/0.5/0.65/0.8 需实测，不能叫“风格强度” |
| LoRA 强度 | 只在可用 LoRA 风格下显示 | 由各风格已验收范围决定，不为文字模板伪造数值强度 |
| steps/CFG/采样器 | 第一阶段保留当前验收值 | 不将 SDXL 常见数值直接套入 Krea 2 |
| 负向提示词 | 当前隐藏，导入非空值时明确不支持 | 原始负向词保留在来源文件中，不静默声称已生效 |
| 提示词增强 | 单独开关，默认关闭 | 若后续启用，先合成风格再增强，并保存最终文本，避免覆盖风格 |

## 现在如何使用内置与自定义风格

### 使用内置风格

1. 打开 MyTools → 工具 → AI 图片生成，选择 Krea 2 和文字生成，或上传一张底稿选择图生图。
2. 使用下方命令合成提示词，也可以打开 JSON 手动用主体描述替换 `{prompt}`。
3. 将输出的整段文本粘贴进 App 提示词框，选择尺寸后生成。风格模板不会自动加载 LoRA。

在仓库根目录运行：

```bash
python3 docs/research/2026-09-14-image-styles/style_pack.py --list
python3 docs/research/2026-09-14-image-styles/style_pack.py \
  --style watercolor --prompt 'a mountain lake at sunrise'
```

主体可用中文；例如把 `--prompt` 内容改为“清晨湖畔的一间木屋”。长文本也可用 `--prompt-file /absolute/path/subject.txt`。工具只合成文本，不连接服务或花费 GPU 时间。

### 新建自定义风格

1. 复制 [自定义示例](examples/custom-styles.json) 到个人文件，例如 `/tmp/my-image-styles.json`。
2. 修改 id、name 和 promptTemplate。id 用小写字母、数字和短横线；不要与内置 id 重复。name 是风格名称。
3. promptTemplate 写**媒介 + 笔触/材质 + 配色 + 光线 + 构图习惯**，保留恰好一个 `{prompt}` 给每次变化的主体。不要把固定人物或物件写进可复用风格。
4. 保留示例中的 kind、modes、compatibleModels 和空 negativePrompt。保存 JSON 后运行：

```bash
python3 docs/research/2026-09-14-image-styles/style_pack.py \
  --custom /tmp/my-image-styles.json \
  --style custom-soft-ink --prompt 'a small cabin beside a lake'
```

5. 把结果粘贴到 App 测试。固定主体、种子、尺寸，以无风格输出作对照；仅改变风格描述。满意后保留配置文件，下次只换主体。
6. 在 styles 数组追加对象即可增加多个自定义风格。修改已有配置时增加 version 便于识别，但离线工具不替你保留历史版本；需要自己留存旧文件。

模板字段最多 2000 字符，最终提示词最多 4000 个 UTF-16 单元，与 App 长度计数一致。工具拒绝重复 id、多占位符、未知占位符、非空负向词和不支持的模式。

### 从图片提炼自己的风格

1. 使用已上线的“图片反推提示词”上传样图并取得描述。
2. 从描述中保留笔触、材质、配色、照明和画面组织；删去人名、主体、具体物件和位置细节。
3. 按上述方法形成 `promptTemplate`，把主体位置换成 `{prompt}`，存入自定义 JSON。
4. 换至少三种主体试用，例如山水、室内、物件，检查是否误带入样图内容。

这条路径是把视觉特征转成文字，不能保证复现原图的精确风格。当前反推返回整图描述；“仅提取风格”应作为独立的新提取目标实现，不能只给现有按钮改名。

### 更稳定的自定义 LoRA（进阶路线）

准备风格统一、主体多样且有使用权的训练图及对应描述，按照 Krea 2 训练流程在 RAW 基础模型上训练；在 Turbo 推理链路验证。训练图数量、步数、学习率需随数据与训练器实测，不给出未经本机验证的一键参数。产物需登记基础模型、触发词、许可、权重摘要与推荐强度。普通用户使用的是登记后的风格卡片，模型训练与权重安装由独立管理流程承担。

## App 与后端正式接入设计（待实现）

### 数据与接口

- `image_style`：稳定 id、来源 BUILTIN/USER、owner_id、名称、当前版本、删除状态。内置不可由普通用户覆盖。
- `image_style_version`：不可变 version、kind、模板、模型/模式兼容范围、来源许可、创建时间；LoRA 增加受管 assetId、trigger 和强度范围。
- 私有样图沿用上传账户隔离；默认不分享，不把用户模板加入全局目录。
- 建议网关接口前缀 `/api/app/v1/image-generation/styles`：GET 列表、POST 私有新建、PUT `/{id}` 新版本、DELETE `/{id}` 隐藏。这里只是设计，现网尚未提供这些接口。
- Create 增加可选 `styleId`、`styleVersion`；不传则保持原行为。用户样式内容通过私有风格接口保存，任务提交只引用确定版本。
- 所有权检查必须覆盖列表、详情、修改、删除、创建任务；模板长度、最终提示词长度与兼容模式均在后端校验。错误码沿用集中管理，新编号实现时分配。

### 合成与历史

服务端先按现有“账户 + 幂等键”找旧任务，找到则返回旧快照；新任务再解析风格版本、检查所有权并合成一次。

```text
用户主体 + 已选择的风格版本
    → 服务端检查 → 字面替换 → effectivePrompt
    → 保存原始主体、风格完整快照、最终提示词、工作流修订
    → 调度器校验任务参数 → 固定版本执行包 → ComfyUI
```

新增 `originalPrompt`、`effectivePrompt` 与 `styleSnapshot`，明确现有 prompt 字段的兼容语义；Executor 只用固化的最终提示词，不再读取实时风格库。同步更新 Scheduler 参数 schema 和新的不可变执行包。发布不能就地改写 `image_generate/1.1.2`。

同幂等键同请求，即使风格后来修改/删除也返回原任务；同键请求体改变返回冲突。已提交任务与历史保留风格快照，删除风格不破坏作品。普通“重试”使用原快照，“使用最新风格再创作”明确创建新请求。保存用户主体与最终文本，避免从历史再次套用模板。

### 页面与自定义操作

正式入口建议放在提示词下方：**风格 → 无风格 / 内置 / 我的风格**。卡片显示名称、样例、适用模型和“文字风格/LoRA”类型；样例统一主体生成，保留风格版本和种子。

上线后的自定义操作应为：风格 → 我的风格 → 新建 → 填名称和风格描述 → 预览合成文本 → 试生成 → 保存。内置卡片提供“复制为我的风格”。用户只编辑风格描述，界面自动处理占位符；高级 JSON 导入作为补充。现在应使用前文 JSON 操作，不能引导用户寻找尚不存在的按钮。

切换账户时清空私有风格缓存。反推模式不应用生成风格；反推结果“用于创作”沿用先前已验收回填规则，另提供“保存为风格”时先进入编辑提炼步骤。

### 验收与发布顺序

1. 先实现 24 个文字风格、私有 CRUD、任务快照与页面；无需新增模型权重。
2. 对 24 风格用固定 3 个主体、2 个种子和相同尺寸生成对照，合计 144 张，加无风格对照；评估风格可辨识度、主体遵循和失败率。该数量是建议测试矩阵，本次未执行。
3. 验证模板修改/删除后的重试、账户隔离、长提示词、旧客户端兼容，以及文生图和图生图均确实收到最终文本。
4. 分批验证 LoRA（建议从水彩、墨刷、复古动漫开始）；新增权重必须有摘要、显存与耗时记录，失败不影响已上线文字风格。
5. 独立图片风格参考最后启用，验证一张/两张参考图与所有权，再开放对应门禁。

回退优先撤下新风格入口与新任务路由，保留已有任务快照和所引用的版本/资产。研究资源包与部署发布包分离，不把原始第三方 Python 插件装进生产服务。
