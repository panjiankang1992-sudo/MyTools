# MyTools PDF 分割：APP UI 与交互设计

> 范围已扩展为统一「PDF 工具」。入口、通用输入和 API/MCP 命名以[最新总体方案](./2026-09-26-pdf-toolkit-design.md)为准；本文保留分割子能力的详细规则。

日期：2026-09-26。状态：设计草案，尚未实现。对应 [后端与 MCP 方案](./2026-09-26-pdf-split-proposal.md)。

设计基于仓库现有 HarmonyOS APP，而不是另建 Web 工具。可视布局见 [四屏设计示意](./pdf-split-ui-board.svg)，图中内容为示意，不是可运行 APP 或真机截图。

## 1. 目标与产品语言

目标用户：整理试卷、教材双页扫描、拆章节或提交附件的 MyTools 用户。核心任务：看见切线、确认页序、取得结果。

主入口“工具 → PDF 分割”，副标题“裁切双页、按页码拆文件”。工具搜索词覆盖 PDF、分割、拆分、试卷、对半、裁切。最近使用只记 `pdf-split` 工具 ID，沿用既有最多 3 项规则，不记录文件名、路径或正文。

PDF 二级工具页隐藏一级底部导航。顶栏“返回 / PDF 分割 / 历史记录”；后台任务可返回工具首页，不阻塞整个 APP。

不使用“垂直/水平”作为唯一标签：

| 用户可见文案 | 补充说明 | API |
|---|---|---|
| 左右分割 | 竖向切线，一页变两页 | VERTICAL |
| 上下分割 | 横向切线，一页变两页 | HORIZONTAL |
| 裁切页面 | 把一页切成多页 | PAGE_CUT |
| 拆分文件 | 按页码拆成多个 PDF | FILE_SPLIT |
| 先左后右 | 左1、右1、左2、右2 | LEFT_TO_RIGHT |

“第 1 页”默认表示文件页序；发现印刷页码或 PDF 页标签时显示“文件第 1 页 · 标签 9”，不要把标签当 API 页序。

读取当前 `app/entry/src/main/ets/theme/AppTheme.ets` 后确定采用现有绿色主题。`app/docs/UI_DESIGN_SPEC.md` 中蓝色说明较旧，本模块不借此更改全 APP 主题。

| Token/尺寸 | 值/规则 |
|---|---|
| 页面背景 | `AppTheme.background`，当前 #F3F6F4 |
| 内容表面 | `surface`，当前 #FFFFFF |
| 主色 | `primary`，当前 #0DA678；选中浅底 `accentSoft` #DDF4EA |
| 主/次文字 | #1E2622 / #59645E |

| 页面水平边距 | 20 vp；窄屏可 16 vp |
| 容器/输入圆角 | 容器 18 vp，输入 16 vp，复用主题常量 |
| 页面标题/分区标题/正文 | 22/17/14～16 fp，遵循系统字体缩放 |

主体用留白和分割线组织，避免“卡片套卡片”。主按钮每屏只有一个。示意图和真实页面明确区分，未取得服务端缩略图不显示伪造页内容。

```text
工具首页
└── PDF 分割
    ├── 选择文件
    │   ├── 本机文件选择器
    │   └── 我的云文件选择器
    ├── 上传/检查/解锁
    ├── 编辑配置
    │   ├── 裁切页面
    │   ├── 拆分文件
    │   ├── 选择处理页（全屏面板）
    │   └── 分割预览（全屏）
    ├── 处理进度
    ├── 结果
    │   ├── 阅读结果
```

不在每个设置后增加确认页。用户明确点击“开始分割”即可创建新结果。仅当文档特性造成实际行为变化时展示对应提示；P0 不支持的特性直接阻止提交。

## 4. 页面 A：选择文件

```text
‹                     PDF 分割              历史

把双页试卷，拆成单页
也可以按页码拆成多个文件

       [ 双页 → 单页 × 2 的线性示意图 ]

[                  选择 PDF 文件                 ]
                   从我的云文件选择

文件会上传至 MyTools 处理，原文件不变。
支持范围以服务器返回的限制为准。

最近任务
第一单元.pdf     4 页 · 已完成              ›
```

- 本地选择器只显示可选 PDF；同时做后缀、MIME 和服务端解析校验，不能只看后缀。
- 取消系统选择器保持当前页，不报错。
- 云文件入口复用现有文件选择能力；如果当前账户无可用云来源，显示说明和本地选择入口。
- 首次网络加载 capabilities 失败时保留页面并提供重试，不假设服务可用。
- 空历史不显示空白列表；历史只展示本人任务。切换账号立即清空上一账户的文件/结果状态。
- 文件选中但未上传前可展示文件名和大小；页数必须等解析结果，不根据文件大小猜。

## 5. 页面 B：上传与检查

上传行显示“正在上传 3.2 / 8.0 MB”，由真实发送字节更新；解析时显示“正在检查页数和页面尺寸”。上传和处理进度分开，不把上传 100% 当作分割完成。

密码对话框：“此 PDF 需要密码才能打开”，安全输入、显示/隐藏密码、取消/解锁。不保存到普通偏好，不在错误 toast 回显。已有权限但禁止修改时明确显示“此文件不允许修改，请使用有权限的副本”。

支持状态：

| 状态 | 页面表现 | 操作 |
|---|---|---|
| 上传中 | 字节进度、文件名、取消 | 取消后关闭上传会话 |
| 上传中断 | 保留已选文件和大小 | 重试上传、换文件 |
| 检查中 | 骨架缩略图、检查提示 | 可返回，任务后台继续 |
| 加密 | 密码输入面板 | 解锁或换文件 |
| 损坏/超限 | 原因及有效限制 | 重新选择 |
| 不支持的签名/表单/注释 | 指明具体特性及限制 | 返回或换副本 |

返回后可通过历史恢复已创建的检查任务。前端不把自己的请求取消当作服务端任务已取消。

```text

│                  ◉ 50%           │
│                  ┊               │
└─────────────────────────────────┘

分割位置       [−]      50.0%       [+]
阅读顺序       先左后右                       ›

输出方式       一个 PDF                       ›

预计 2 页 → 4 页 · 1 个 PDF
```

### 6.1 分割线

- 先按有效可见页面 fit-contain，记录纸张实际区域；触点先扣除留白、缩放和平移，再映射到归一化坐标。
- 初始 50%；接近中线时吸附，可轻触“重置 50%”。数字输入支持 0.1% 精度；加减按钮每次 0.5%。最终使用服务端返回的规范化值。
- 手指拖动切线热区调整；双指缩放/平移用于看清内容，不改变切线百分比；提供“适应页面”恢复。
- 拖动时只更新线框与切片编号，不反复重传 PDF。松手或停顿后生成权威预览；显示“正在更新预览”。
- 当前预览对应旧配置时主按钮暂不可用，并显示原因；只允许提交当前 revision 的 READY plan。
- 上下模式切换后切线改为水平、顺序改为先上后下，百分比可保留；页上箭头清楚示意输出方向。
- P0 设置应用于所选全部页面；P1 再提供“仅当前页”。首期 UI 不放无效开关。

### 6.2 页面选择

点击“处理页面”打开全屏选页面板：缩略图网格、全选、清空、范围输入、已选计数。手机两列，平板自适应；列表虚拟化、按需加载缩略图。

范围输入可写 `1-3,5,8-10`，即时转换为闭区间数组；负数、0、逆序、非数字、超过页数均在字段下报错。重复范围合并。P0 未选页保持原位置，不悄悄删除。

例如总 5 页，只处理 2–4 页，两个区域/页：输出 `1 + 3×2 + 1 = 8` 页。UI 显示“处理 3 页，其余 2 页保留；预计共 8 页”。不能只显示选中页的翻倍结果。

### 6.3 输出与警告

裁切默认一个 PDF，避免把本次需求意外变成四个文件。输出文件名默认“原文件名_分割.pdf”，用户可改显示名；服务端仍生成安全存储键。

设置区下方有常驻简短帮助“版面裁切不会安全删除框外内容”，点击可展开解释。不是每次操作都弹警告确认，不遮挡正常试卷场景。

任何检测到的特性损失都在预览前可见；如果 P0 不支持，按钮禁用并显示具体原因，不能只变灰。

## 7. 页面 D：拆分文件

使用同一个文件摘要和顶栏，切到“拆分文件”后配置区替换为：

- 模式选择：“按页码范围 / 每 N 页 / 每页一个文件”。
- 页码范围：`文件1 [1] 到 [3]`、`文件2 [4] 到 [8]`，支持添加/删除范围。
- 每 N 页：数字步进器和即时文件清单；页数必须 >0。
- 输出摘要显示“将生成 3 个 PDF，共 12 页”；每个输出卡片列出页范围。
- 多文件默认准备 ZIP，也允许分别保存；ZIP 创建是任务的一部分，下载时不临时压缩阻塞。
- 输入“1–4、3–6”时提示“第3–4页将在两个文件中重复”；默认要求用户修正或明确选择允许重复。

首期不展示灰掉的书签、体积、智能识别选项；待能力接口开放后增添“更多方式”，没有开发完成的模式不应作为可点入口。

## 8. 页面 E：分割预览

手机全屏展示一个输出页，上方切换“原页 / 分割后”；底部横向缩略图条和页号，支持翻页。提供“查看全部”网格浏览。

每页来源清楚标为“输出第 2 页 · 原第 1 页右侧”。不把这些来源标记写进 PDF 正文，也不添加水印。

本例摘要固定为：

```text
原文件 2 页 → 输出 4 页
1 个 PDF · 接近 A5
顺序：原1左 → 原1右 → 原2左 → 原2右
```

只有获得服务端计划后才展示权威页数/尺寸。修改配置返回编辑器，保留同一文件；已有计划不原地改变，创建新 revision。

无障碍顺序：页面标题 → 输出统计 → 当前预览页及来源 → 翻页控件 → 配置修改 → 开始分割。切线须能通过数字字段操作，不能依赖精细拖动。

## 9. 页面 F：处理进度

顶部显示文件名；中部显示当前阶段：排队、正在分割、校验结果、保存结果。能测量时显示“已处理 3 / 4 页”；只有未知阶段时用循环指示器。

主动作“返回工具，后台继续”，次动作“取消任务”。点击取消后立即变为“正在取消”，收到服务端终态后才显示取消成功。任务已完成时取消请求回显完成结果。

APP 进入后台停止高频轮询，返回时按 jobId 刷新。轮询按 1s→2s→5s 退避并遵循 retryAfterMs，网络失败不创建重复任务。可复用项目推送能力，但 P0 不依赖推送才能正确完成。

失败页面显示可理解的错误及下一动作：超时重试、重新解锁、修改范围、重新预览；复制诊断信息仅含 jobId/错误码/版本，不含密码和文档内容。

## 10. 页面 G：结果与历史

```text
‹                     分割完成
                         ✓
                   已生成 4 页
                  原 2 页 → 4 页

[     第1页     ] [     第2页     ]
[     第3页     ] [     第4页     ]

第一单元_分割.pdf
1 个文件 · 实际大小由服务端提供
结果保留至 YYYY-MM-DD HH:mm

[                   预览 PDF                   ]
[ 保存到设备 ]                [ 保存到云文件 ]
                     用相同设置再处理
```

- 预览 PDF 复用现有 PDFKit 能力，下载受控缓存后打开，不把一次性下载票据直接当作可多次 Range 的阅读器源。
- 保存设备使用系统保存选择器，成功写入并校验后显示“已保存”；用户取消不报错。
- 保存云文件必须由用户选目标目录，通过现有/新增 Drive 导入边界创建受管文件引用；同名默认安全改名，不覆盖。
- 分享只在用户主动使用系统分享时进行，不能默认公开链接；后台下载完成不等于已分享到其他应用。
- 历史按当前账户分页，显示原文件名、模式、时间、状态、页/文件数量和到期时间。
- 结果过期保留任务摘要和“重新选择文件处理”，不显示可用下载按钮；若原输入仍合法可用，允许复用来源。
- 清理/删除明确显示“仅删除此任务结果，原文件保留”。用户已保存到云盘的独立引用不随临时任务一起清理。

## 11. APP 状态与实现边界

建议 `PdfSplitPage` 管理有限 UI 状态，API 与算法校验拆文件：

```text
EMPTY → UPLOADING → INSPECTING → EDITING
                       ↘ PASSWORD_REQUIRED
EDITING ↔ PREVIEW_PENDING → PREVIEW_READY
PREVIEW_READY → SUBMITTING → TRACKING → RESULT
                                  ↘ FAILED / CANCELLED / TIMED_OUT
```

文档、计划和 job 各有自己的状态，不用一个 `isLoading` 覆盖全部。最近有效 planId 绑定 `documentId + revision`；编辑改变立即使其不可提交。

账户切换、退出登录、文件更换必须递增请求代次，忽略旧网络响应；持久化恢复只存 owner-scoped jobId 与非敏感设置。密码不持久化，文件 URI 遵循系统授权有效期，不能假定重启后仍可读。

API errors 由 `PdfSplitPolicy` 映射本地资源文案；未知码显示安全通用错误与诊断编号，不直接把后端异常字符串展示给用户。

新增字符串、图标、可访问性描述通过 APP 资源管理；示意文案不作为硬编码业务标识。

## 12. 自适应与 UI 验收

- 手机：单列，预览在上、设置在下，底部操作固定但不遮挡内容。
- 平板/横屏：左侧预览约 60%，右侧设置约 40%；底部结果摘要跟随设置栏。旋转时保持相同归一化切线和文档页序。
- 大字体：配置行可改为上下布局，按钮可换行，不压缩到不可触控；PDF 纸张仅缩放，不按正文系统字号重排。
- 读屏：切线报“左右分割，位置百分之五十”，步进按钮报调整方向；缩略图报来源/输出序号。
- 黑暗模式：使用项目最终主题能力；本设计图展示当前浅色，不额外宣称暗色已完成。
- 验收必须在真实 HarmonyOS 设备执行上传、拖动、返回后台、恢复、下载保存；设计图不能替代设备验收。

关键任务验收：用户选中本例后不改默认设置，看到“2 页 → 4 页，1 个 PDF”，可以检查预览并开始；下载结果顺序为原1左、原1右、原2左、原2右。整个过程中不要求理解 CropBox、DPI、MCP 或后台任务 ID。
