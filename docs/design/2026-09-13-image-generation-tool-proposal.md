# MyApp 图片生成工具方案 v0.2

日期：2026-09-13。状态：仅设计；按用户要求，远端验证不通时不继续接入，尚未实现或部署生图服务。

## 1. 目标与结论

在 MyApp「工具」中增加「图片生成」：输入文字、选填参考图或底稿，选择 Ubuntu 本地模型或远端模型，异步生成图片、查看历史、下载和继续创作。

首选架构：原生 App 页面 + 独立 image-generation-service + 现有 Scheduler/Executor + 本地 ComfyUI/Krea 2 与远端 Provider 适配器。模型切换发生在下一次任务提交前，已提交任务固定模型、参数和版本。切换模型不保证相同画面或参数语义。

本地 Krea 2 以文生图优先，风格参考单独验收后开放。主体保留编辑、蒙版编辑、姿势锁定不能因为支持参考图片就自动标记为支持。远端复用当前加料资源的登记信息与凭据管理方式，但须先确认服务商是否提供可用的图像输出模型。

## 2. 已知依据与未验证事项

- 当前仓库 App 位于 app/entry，Index.ets 的工具页已有搜索、最近使用和工具条目，方案沿用入口与 AppGlass/AppTheme 体系。这里将用户所称 MyApp 对应到该客户端；实施前确认实际发布端和分支。
- 现有独立 Gateway、Scheduler、Executor 和 Asset Registry 可以复用；不能直接在移动端访问 ComfyUI、调度数据库或供应商密钥。
- 当前加料客户端 NovelProviderClient 按固定 chat/completions 端点、部署标识、精确模型、凭据代次实现文本调用；目前检查到的代码不足以证明它提供通用模型目录或图像输出能力。
- 本次方案引用同一会话刚完成的 Ubuntu 只读实测：RTX 5060 Ti 16GB；i5-14600KF；约 32GB 内存、可用约 18GiB；Swap 8GiB 已用约 7.5GiB；磁盘可用约 658GB。数值为检查时快照，不是容量预留。
- 检查时 Ollama 已安装 qwen3-vl 8b，但未驻留显存；它用于视觉理解/标签，不是生图模型。尚未进行 Krea 2 本机加载或速度测试。
- 官方产品交互资料用于模式参考，本稿没有做像素级界面复刻或视觉可用性实测。

## 3. 界面设计

参考 Midjourney Create 的提示词、参考图、生成记录与复用入口，以及 Krea 对风格参考用途的明确区分；在手机上采用单栏创作页，避免照搬桌面多栏和节点编辑器。

入口：工具 → 图片生成。支持工具搜索和最近使用。页面内设「创作」「作品」切换；队列状态嵌入创作记录，不增加一级导航。

### 创作页布局

1. 顶栏：返回、图片生成、作品记录。
2. 模型选择胶囊，例如「本地 · Krea 2 Turbo」。点击打开底部面板，按本地/远端分组，展示能力、可用状态、已测速度或价格信息；未知价格显示未知，不写免费。
3. 模式：文字生成 / 参考生成 / 修改底稿。依据模型能力显示可选模式；不支持项说明原因并提供切换模型入口。
4. 文字输入框：占据主要编辑区域。占位提示包含主体、画风、光线；提示词优化为可选按钮，展示优化前后内容，保留原文。
5. 参考图横向缩略图：从相册或本人服务器素材选择；标注「风格参考」「主体参考」「待修改原图」等用途，支持预览、移除、调整权重（仅在模型支持时）。
6. 常用参数：比例、画质、数量，采用紧凑选项；种子与高级设置折叠。不要向普通用户暴露采样器、节点 ID 或内部路径。
7. 底部固定生成按钮：同时显示当前模型与必要的额度信息。上传中禁用，提交时防重复。
8. 生成记录：展示排队、加载模型、生成中、保存中和结果缩略图。仅显示真实进度；无法获取步数的远端任务使用阶段提示，不编造百分比或倒计时。

### 结果与连续创作

图片详情支持放大、下载原图、保存到本人素材库、复制提示词、再次生成、作为参考图、继续修改。继续修改仅对支持编辑的模型开放；Krea 风格参考按钮文案不能暗示会保持同一张脸。

历史按用户分区，记录输入、模型、工作流版本、尺寸、种子和衍生关系。切换设备/退出 App 不终止服务端任务。按张展示批量任务，保留部分成功结果；失败重试只重试失败项。

### 切换模型规则

- 保留文字和已上传素材，重新验证模式、图片用途、数量、比例与分辨率。
- 不支持的设置明确提示重选，不默默改成其他语义。
- 不同模型的 seed、风格强度、负面提示词等不可直接等价迁移。
- 已排队任务不可中途换模型；用户取消后另建任务，历史保留原模型记录。
- 本地失败不自动转远端。用户主动切换远端时，页面明确说明文字和参考图将发送至所选服务商。
- 本地模式的提示词优化也必须留在本地；不能通过隐藏的远端文本调用破坏本地边界。

## 4. 模型资源配置

扩展现有模型资源概念，生图服务引用 resourceId 与 credentialRef；不把小说专用凭据、阶段票据或正文协议直接复制成通用图片调用协议。

建议配置字段：

| 字段 | 用途 |
| --- | --- |
| resourceId / displayName | 稳定标识和前端展示名称 |
| location | LOCAL / REMOTE |
| adapterType | COMFYUI / 具体远端协议适配器 |
| modelId / deploymentRevision | 精确模型和配置快照 |
| endpointRef / credentialRef | 服务端管理的端点与凭据引用 |
| capabilities | TEXT_TO_IMAGE、STYLE_REFERENCE、IMAGE_EDIT、INPAINT 等 |
| limits | 宽高/像素、参考图数、生成数量、格式和上传体积 |
| workflowRevision / weightDigest | 本地工作流与权重版本 |
| pricing / quota | 经核验的远端计费规则与预算限制 |
| validationState | 未验证、已验证、禁用、不可用 |

App 仅拿脱敏展示字段及可选参数，不拿密钥、端点或服务器路径。兼容接口名称不代表协议完全一致：应分别处理同步图片、异步任务、base64、临时下载 URL 和多模态图片输出。

远端接入的第一个门槛：用当前加料资源所属服务商的正式模型目录/文档确认图像模型与协议。文本模型可用于用户明确启用的提示词辅助，但不能当作图片生成模型列入选择器。若该资源不提供图像输出，复用管理方式并新增兼容资源配置，不绕过其能力限制。

## 5. Ubuntu 本地 Krea 2 方案

### 权重与内存取舍

官方 Comfy 模型目录中，Turbo FP8 主权重约 13.1GB，INT8 Convrot 约 13.5GB，BF16 约 26.3GB，NVFP4 约 7.67GB；FP8 编码器约 5.24GB，另需 VAE。文件大小不等于峰值显存。

建议先对 Turbo NVFP4 做兼容性试验，配合分阶段加载编码器/扩散模型与 VAE，验证驱动、PyTorch、量化算子和 ComfyUI 工作流组合。它是 16GB 显卡的候选，不是已验证配置；不要依据较小文件体积承诺画质或速度。

若 NVFP4 不兼容，试 Turbo FP8 配合内存卸载、VAE 分块。由于系统仅剩约 18GiB 可用内存且 Swap 占用高，FP8 卸载方案也必须实测，不能默认全量权重同时驻留内存。

风格参考使用官方对应的 INT8 Convrot 模型和 style-reference LoRA 单独验证，不能假设与 NVFP4 文生图共享全部兼容性。MVP 可以先仅启用本地文生图；风格参考验收失败时保持不可选，不冒充已支持。

### 建议初始配置（试验起点）

- GPU 并发 1；batch size 1。
- 初始总像素上限约 1MP，例如 1024×1024；横竖比例由服务端白名单映射到具体宽高。
- Krea Turbo 从官方 8 步建议开始；本地提示词增强初期关闭。
- 用户可选 1/2/4 张，其中 2/4 张由多个串行子任务完成，不能直接变成 GPU batch 4。
- 初期不开原生高分辨率和放大；待 1MP 稳定后，独立验收并启用分块放大。
- 先记录冷启动、热推理、参考图和连续生成的 P50/P95、峰值 RAM/VRAM，再确定生产超时、负载上限和是否延迟卸载；目前不填虚假的秒级承诺。

### 与打标签共存

新增 GPU 资源协调机制，覆盖 ComfyUI 和所有调用 Ollama 的 GPU 消费者。只给生图任务设并发 1 不能防止标签任务同时抢占显存。

获得 GPU 使用权前等待现有推理结束，再按约定释放模型缓存；在整段模型加载/推理/卸载期间持有租约。不能仅依赖空闲显存快照，也不能在标签请求中途调用卸载。租约异常必须确认旧进程不再运行后才移交资源，不能只凭超时重复启动。

采用有等待时长上限的公平队列；批量图片每完成一张允许其他类型任务进入，避免下载标签被长批量饿死。OOM 时释放当前工作流、标记失败并给出降低画质建议，不自动转远端，也不无限重试。

ComfyUI 使用独立受限服务用户与磁盘工作目录，只监听本机或受限内网。工作流固定并版本化，App 不得提交任意节点图。权重/输出放磁盘目录，不放 tmpfs 的 /tmp。为进程配置经实测确定的内存上限，确保现有服务保留余量。

## 6. 后端职责与任务生命周期

建议新增轻量 image-generation-service，负责用户授权、资源目录、请求校验、业务状态与作品历史。Scheduler 负责可靠调度，Executor 负责运行受控图片任务；ComfyUI 只是本地推理运行时，不作为 App 后端。

流程：

MyApp → Gateway → Image Generation Service → Scheduler/Executor

Executor → 本地 GPU 协调器 → ComfyUI/Krea 2

或 Executor → 远端 Provider Adapter

结果 → 受管存储 → Asset Registry → 用户作品记录 → App

现有 Asset Registry 可复用派生资产关系、幂等登记与执行 fence。作品浏览是用户功能，需由新服务提供授权后的资源访问；不能直接暴露内部资产 API。

建议图片业务状态：UPLOADING、QUEUED、LOADING、GENERATING、PERSISTING、SUCCEEDED、PARTIAL_SUCCESS、FAILED、CANCEL_REQUESTED、CANCELLED、UNKNOWN。它们由图片业务层映射现有 Scheduler 状态，不为展示需求强行改写通用调度状态机。

远端请求发送后连接断开时先按 providerJobId 查询或对账；无法确认结果时进入 UNKNOWN，禁止盲目重发造成重复扣费。没有供应商取消能力时显示取消结果跟踪/取消请求中，不承诺已经停止计费。

客户端重试使用同一幂等键；参数指纹不一致则拒绝复用。输入和最终结果存为受管资产，临时供应商 URL 不能成为历史作品的唯一来源。下载结果时校验目标地址、类型、体积和像素上限。

### 建议业务 API

- GET /api/v1/image-generation/models：可用模型、能力和允许参数。
- POST /api/v1/image-generation/uploads：本人素材上传及归属验证。
- POST /api/v1/image-generation/jobs：resourceId、prompt、mode、references、size、count、seed、idempotencyKey。
- GET /api/v1/image-generation/jobs/{id}：阶段、逐张结果、可执行操作。
- POST /api/v1/image-generation/jobs/{id}/cancel：取消请求。
- GET /api/v1/image-generation/works：作品与历史分页。

以上是建议契约，不是现有可调用接口。提交请求时快照资源版本、凭据代次、提示词原文/优化版、工作流、参考资产和种子；凭据本体不进入任务参数。

## 7. 分期与验收

### P0：部署可行性与资源确认

1. 在 Ubuntu 隔离目录试跑 Krea Turbo 量化候选，固定版本并校验下载文件。
2. 人物、风景、产品三类文生图；冷/热启动；连续生成 20 张；取消/重启/OOM恢复。
3. 风格参考独立验证，观察是否出现不必要的内容复制与质量退化。
4. 与真实打标签负载交替执行，观察标签等待时长、Swap 和服务健康。
5. 验证当前远端资源是否有真正的图像输出模型、编辑能力、计费与查询协议。

P0 不通过的能力不出现在可用模型列表。若 16GB/32GB 环境无法达到稳定运行门槛，应明确报告 Krea 本地能力暂不可上线，而不是悄悄换模型。

### P1：可用首版

交付工具入口、原生创作页、模型选择、能力驱动参数、可选参考图、异步任务、逐张结果、历史、下载、取消及错误处理。本地至少文生图通过验收；远端不作为首版交付前提，能力和访问验证完成前仅保留适配接口及不可选的待验证资源项。参考图只对已验证路径开放。

远端底稿编辑若已验证即可支持；否则模式显示不可用，不能用风格参考替代。首版不承诺专业画布、姿态锁定、角色 LoRA 训练或批量自动发布。

### P2：编辑增强

按已验证模型加入蒙版编辑、原图对比、版本树、参考强度、风格收藏和分块放大。人物一致性采用明确样本评测，不以单次成功替代能力证明。

### 发布验收门槛

- App 从创建到资产入库、历史重开完整成功，不能只用直接调用模型替代端到端验收。
- 图片服务拥有最小必要的 Scheduler 任务权限；此前旁路标签验收出现过 403，必须在新功能上线前验证合法业务身份。
- 切换模型时无参数静默丢失；本地任务不向远端发送输入。
- 断网重连、重复点击、应用退出、服务重启、远端未知结果均不导致重复任务/重复扣费。
- 多用户任务、参考图和作品不能相互访问；本地路径、凭据与内部节点信息不进入 App 或普通日志。
- 回滚只停止新版本分流，保留已完成作品，并避免旧/新 worker 同时执行同一任务。

## 9. 远端接口最小验证与设计调整（2026-09-13）

用户指定服务根地址为 `https://api.sillytraven.dev/api/ai/v1/`，授权沿用现有密钥。通过配置的 Ubuntu SSH 通道，在服务器内部读取既有加料凭据，以 Bearer 认证发送一次 `GET /models`，未输出或复制密钥。

结果：HTTP 403，Cloudflare 错误 1010（browser_signature_banned），返回说明当前客户端特征被拦截，并标记不可重试、需要站点所有者处理。因此停止探测，没有发送生图请求，没有更换客户端特征或尝试绕过拦截。

这次结果只能确认该测试请求被边缘访问规则拦截，不能证明密钥错误、文本接口故障或服务商不支持图像生成。图像模型清单、协议、费用与图片输出仍未验证。此前文字调用可用不等于本次模型目录请求可用。

设计调整：

- 模型选择保留“本地 / 远端”分组；远端资源显示“SillyTraven · 待验证”，不可选择生成，并解释“尚未完成连接与生图能力验证”。
- App 不展示密钥、原始 Cloudflare 响应或内部凭据路径；管理员诊断保留状态码和错误类别。
- 对当前加料配置采用服务端资源引用，不修改现有小说调用链，也不猜测生图模型 ID 或接口路径。
- 远端通过验证后按能力开放文生图/参考图/编辑，不要求重新设计页面。
- 首版可按本地 Krea 2 路径规划，仍须先通过本地资源验收；本轮仅完成设计，不下载权重或启动新服务。
