# 全文改编与风格模板改造

## 差距与边界

上一轮 40–80 字是验收意图，不是用户要求。另有实际产品限制：Executor 强制插入协议限制总增补、单片段长度并原样拼回原文；Reader 字面事件锚点、数字及长度比例检查会拒绝合理的全文换写。改为新的全文改编协议，不把验收样例变成通用规则。

新的“自由”指写法、风格、描写深度及改写幅度不被小额增补规则限制。保留用户原本要求的核心剧情、因果、人物关系、知识边界和章节衔接；原书永不覆盖。模型上下文、响应长度、超时、授权和资源上限仍是技术边界，不宣称所有内容均可无限生成或供应商永不拒绝。质量评审保留，不将模型自称无限制当作绕过协议或失败处理的理由。

## 交互

目录改编入口、结果页优化/重改保持不变。提交区新增后端加载的风格下拉框，默认“自由改写”，展示模板简介；APP 不提供新增、编辑或删除模板。暂保留本次意图必填，等待用户对“只选模板也可提交”的偏好答复。提交后冻结所选代码和版本，网络恢复重放不能换模板。历史/详情展示当时的模板名称和版本。

初始模板：自由改写、细腻心理、电影叙事、悬疑张力、爽文节奏、古风雅致。每个模板自带风格提示词，不改变上述剧情边界。模板获取失败时不偷偷退回另一风格提交。

## 数据与接口

- 模板采用稳定代码 + 不可变修订，当前修订单独登记。发布新修订用 expectedLatestVersion 并发控制与独立幂等键；已发布的内容不覆盖。
- APP 登录态 GET `/api/app/v1/reader/adaptation-style-templates` 只读摘要，返回代码、版本、名称、简介；无管理代理路由。
- Reader 对应只读接口在既有受保护 reader-state 路径。发布接口位于独立内部管理路径，使用独立管理 token 文件校验，不能用普通 APP JWT 或 Reader 服务令牌发布。
- 创建/优化/重改增加可选成对字段 `templateCode`、`templateVersion`。字段参与幂等指纹；旧请求保持旧指纹及重放兼容。
- 新任务原子保存模板快照、提示词摘要及合成后的生成意图。用户原始意图单独保持；执行只读取冻结值，不在后台重新读取“最新模板”。模板正文不由 APP 提交。
- 新模板任务固定使用 v2 全文 Prompt/约束协议，已有 v1 历史、收据与进行中任务继续按旧协议处理。

## 生成与校验

v2 规划继续使用宿主编号的原文证据；成文/修复直接返回完整章节，不走插入片段组装。评审继续使用结构化十维检查。Reader 对 v2 不要求原句、事件锚点或数字的字面拼写不变，也不以固定扩写比例拒绝结果；原文事实、顺序、结尾及人物连续性由绑定原章和邻章的评审校验。约束版本随任务冻结，旧 v1 的恢复不能被新实现重新解释。

## 添加模板技能

提供 `$add-adaptation-template`，通过 HTTP 后端管理接口发布，不改数据库或 APP 源码。技能携带可重复运行的请求脚本，管理令牌只从私有文件读取并放入请求 Header，不进入命令参数、输出或仓库。默认先检查当前模板及版本，按用户明确要求发布；不因“查看模板”执行写入。同一发布重试复用同一幂等键。可通过当前配置的 SSH 在服务器回环接口运行该脚本，不采用其他部署传输通道。

## 实施与验证

依次实现迁移/模板仓储和管理认证、请求与快照扩展、v2 生成及语义校验、Gateway/APP 下拉与持久收据、技能。集中验证：权限隔离、默认模板、版本发布/冲突/幂等、模板快照不漂移、旧请求兼容、完整换写可通过而剧情冲突不可采用、APP 切换账户及请求重放保留模板。只对变更模块构建，部署前合并结果一次验收，不重跑已有模型样例碰运气。

## 已实现接口

APP 读取目录：`GET /api/app/v1/reader/adaptation-style-templates`。沿用 Gateway 登录认证及响应信封，数据字段为 `items: [{code, version, name, description, promptSha256}]`。APP 不能传入 prompt、模型地址或 owner。

创建、优化、重新改编在原请求中增加以下成对字段，其余入口保持不变：

```json
{"templateCode":"cinematic","templateVersion":1}
```

历史和详情的版本对象新增可空 `styleTemplate` 摘要。旧历史为空，不猜测其文风。未确认请求的本地日志保存模板代码与版本，重启重试不能切换风格；模板加载失败可单独重试，不丢失已经输入的意图。

管理读取和发布均为 `/api/v1/reader-admin/adaptation-style-templates`，分别使用 GET 和 POST。仅接受独立 Bearer 管理令牌，不提供 Gateway 管理代理。POST 示例：

```json
{
  "idempotencyKey": "publish-noir-unique-operation-key",
  "code": "noir",
  "expectedLatestVersion": 0,
  "name": "冷峻叙事",
  "description": "克制语言与紧凑节奏，突出已有冲突。",
  "prompt": "Use restrained language, terse dialogue and a cool narrative tone. Rewrite freely while preserving established plot, relationships, knowledge boundaries and chapter entry/exit states."
}
```

返回已发布摘要。相同键与相同正文重放原收据；相同键不同正文返回 READER_036（幂等冲突）；乐观修订冲突返回 READER_064；请求所选修订不存在返回 READER_063。模板发布不调用模型、不创建小说任务。

## 配置与上线顺序

- 本轮完成本地实现和打包，**尚未部署现网，也未安装 APP 到设备**。旧现网的插入协议不会因为本地代码改动自动升级。
- Reader 使用新增迁移 V39；首次启动经应用事务初始化六种模板。独立管理令牌文件由运维创建并收紧权限，配置 `reader.adaptation-style-admin-token-file`（环境变量 `READER_ADAPTATION_STYLE_ADMIN_TOKEN_FILE`）。未配置时管理端拒绝发布，APP 只读目录不受影响。
- 上线前验证当前 SSH 连通与正在运行的版本，保留原发布目录和数据库备份。暂时关闭新建改编并确认在途任务状态，再部署 Reader（迁移、初始化）、Executor、Gateway，完成只读健康和权限检查后恢复新建并安装 APP；不得在仅 Reader 升级时提交 v2 任务。
- 不重新运行旧的三版本模型验收。上线验收集中覆盖默认模板目录、一次模板发布/幂等重放、一个明确授权的章节全文改编及历史快照；后端模型成功与 APP 真机交互分别报告。
- 如需回滚，先关闭新建与相关调度，检查 v2 在途任务；旧 Executor 不支持 v2，不能直接让其接管。保留新增表、修订、收据和原书，不做降级删表。

## 本地验证结果

- Reader 改编相关首轮 297 项通过，新增管理鉴权测试及相关回归 36 项通过（两批存在重叠，不相加计算独立覆盖）。覆盖迁移、风格发布/重放、乐观冲突、快照不漂移、旧收据和 v2 语义判定。
- Executor 130 项首轮通过，补充全文 HTTP 协议测试后的相关回归 26 项通过（存在重叠）。模拟服务证明即使旧全局 insertion 开关开启，v2 成文仍提交普通全文请求，不请求 JSON 输出，也不组装插入片段。
- Gateway 最终 20 项通过，覆盖认证目录、禁止 APP 发布、模板字段转发及客户端提示词拒绝。
- APP 请求/响应策略 21 项、账户/持久日志策略 22 项通过；最终 `assembleHap` 成功，产物为 `app/entry/build/default/outputs/default/entry-default-signed.hap`。尚未进行原生设备点击验收。
- `$add-adaptation-template` 已安装到本机 Codex skills 目录，仓库副本为 `skills/add-adaptation-template`；技能格式验证和 3 项回环 HTTP 测试通过。管理密钥未写入技能或仓库；使用技能前仍需部署后端并配置独立管理令牌。
- 未调用外部模型，模拟 critic 测试只验证协议和状态逻辑，不代表真实模型的文学质量或全书剧情一致性已经验收。Maven 测试存在既有 Mockito/JDK 动态 agent 提示，非新增 Java 编译告警；APP 构建没有新增告警。
