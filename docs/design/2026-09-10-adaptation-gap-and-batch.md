## 2026-09-11：后端输出入库校验

实质缺口是：Executor 已检查阶段 JSON，但 Reader 的终态入口此前只验证“有界 JSON 对象”，任意字段也可能先持久化、后在封存规则时才被拒绝。本批新增 `AdaptationOutputSchema`，在 Reader 生成规范 JSON、摘要及任何终态写入之前检查完整 PLAN/CRITIC 白名单、必填字段、枚举、数组/文本上界、码点位置、唯一事实/实体及引用、事件顺序、十项审查维度、失败解释与 outcome 一致性。GENERATE/REPAIR 的 Markdown/HTML 包裹也在 Reader 独立拒绝。

Executor 同步补齐事实引用范围/类别、顺序及整数溢出边界，合法协议保持不变；非法模型结果先归一为无正文的 `READER_041`，避免正常宿主把必定被拒绝的结构反复交给 Reader。绕过 Executor 直接发送非法终态时，Reader 返回 `400/READER_060`，不写原文、JSON、摘要或正式结果，不返还预算、不重新许可 Provider 发送。已有发送仍按合法同收据结算或既有到期恢复收敛，不能把“输入被拒绝”推断成模型没执行。

格式通过不等于内容可信：原章摘要、引用是否确属冻结文本及剧情语义仍由原有 StoryEngine 检查；此次未实现独立内容审核，也未改写既有终态或数据库迁移。

## 2026-09-11：集中改为引文输出协议

根本调整：模型只提交判断及逐字引文，宿主从本次发送票据绑定的可信原文/候选计算摘要与 Unicode code point 坐标。新增默认关闭的 `provider-quote-protocol`，且要求先启用有界格式兼容。请求体写入 `providerWireVersion=quote-v1`，最终发送字节的 SHA-256 仍作为许可与账本绑定依据；不让任务包传入任意提示词或坐标。

- PLAN 线协议 `adaptation-plan-quotes-v1` 不接受模型提供的摘要、sourceStart/sourceEnd；保留意图、事实、实体、剧情锚点、扩充点、禁止变更、末态和视角。引文重复时必须显式提供一基 `occurrence`，实体名称默认取第一次出现；事实内锚点只在被引用事实内定位。不按最近位置猜测，也不补写原文不存在的引文。
- 宿主输出 `adaptation-plan-v2`。v2 的有序锚点明确保护各类原文事实的出现顺序，包括知识边界；不再把所有锚点误要求为 EVENT/STATE，也不重分类事实。v1 原有类别限制保持不变。Reader 仍逐字验源、校验顺序和末尾位置，并在采用前执行确定性及十维评审。
- CRITIC 线协议 `adaptation-critic-quotes-v1` 同样只返回证据引文和判断；宿主绑定当前候选及约束摘要，转换为原有严格 critic-v1。UNKNOWN、FAIL、BLOCKED 及问题说明原样保留，无法消歧的证据拒绝；禁止降级到旧协议伪造成功。
- 无数据库迁移、无脚本包变更、无 Provider 自动重发，旧冻结计划可继续恢复；需同步升级 Reader/Executor 后才可打开此隔离配置。

定向验证：Executor 71 项、Reader 165 项，总计 236 项。Reader 首次新测试因重复构造不同身份的冻结快照出错，修正夹具后仅复验该引擎的 9 项并打包，其余已通过用例不重复运行。最终选定报告无失败、错误或跳过；不把这一数字等同于真实模型生成成功。

引文候选已安装在隔离环境。第六次真实 INITIAL 的 PLAN 和 GENERATE 成功，随后 CRITIC 协议失败，整版仍为 FAILED，未产生可公开采用的正文。一次只针对既有候选的独立评审诊断虽返回十维 PASS，确定性核对仍发现缺失剧情锚点；诊断未被写成业务成功。这体现当前差距已从 PLAN 契约推进到实际评审稳定性和加料守约质量，但不能称完整闭环通过。继续用原句保留型样例做一次有界正式链路验证，细节和最终状态见验收记录。

该原句保留样例形成第七版，实际 PLAN/GENERATE 成功但 CRITIC 仍协议失败。最终成功采用 0、保留失败 7；七版历史和详情通过重启一致性检查，第七版幂等重放无新增调用。四个临时服务停止、待结算调用 0，生产四服务 active、v2 未变。下一开发重点是无正文泄漏的评审失败分类和可复现适配，不是继续相同请求试跑；优化、重新改编、成功对比和 APP 端完整验收仍未通过。

## 2026-09-11：有界增补模式修复

新增默认关闭的 `provider-insertion-protocol`：生成和修复返回有预算的增补片段，由宿主按原文固定编号位置组装，原句、顺序和末句不交给模型替换。该模式面向保留原文的增补改编，不等同于任意整章措辞重写；新增描写仍须独立语义审查。编号由原文决定，派生 PLAN 只限制可写位置，防止优化时丢失旧增补位置；旧自由改写基文不可还原时明确拒绝，不偷换优化基文。

## 2026-09-11：规划引用可靠性修复

根因是职责分配：旧 PLAN 同时让模型描述事实、复制原文引文、选择事实内锚点并维护交叉引用；后端又要求所有复制字段逐字匹配。上次 HTTP 200 后出现 MISSING_QUOTE，证明故障在协议验源而非鉴权或连接。该响应未保存原始字段，不能断言究竟是实体名、事实引文、锚点还是 occurrence 导致。本次不增加模糊匹配、自动改引文或盲目重试。

在显式原文保护型增补配置内，PLAN 改为 `adaptation-plan-refs-v1`：

- 后端按 Unicode 码点生成有序原文目录，每段 2..120 码点，末尾单码点从前段借一位，整份原文可以逐段重建。原文及完整目录都发送，优化基文不参与规划目录，仅成文阶段使用。
- 模型只返回意图判断、事实的 sourceId/类别/描述、扩写点 sourceId/类型/目的、禁止变更和视角。整数编号与显式 S 编号为同义表达，非法类型或越界编号失败。模型不再回抄原句、实体名、字符位置、事实 ID 或结尾锚点。
- 宿主从本次实际发送的原文重建目录，绑定引文和坐标、分配事实 ID、按原文顺序去重文字锚点，并始终加入必要的原文边界保留约束。重复段不伪装成可用第一次出现定位的不同事件；具体重复内容仍由原文保护组装保留。
- 输出继续使用 Reader 已支持的严格 plan-v2，CONFLICT 原样保留。此模式不需要模型补充实体字符串清单，因为生成和修复无法删除或替换任何原句；Reader 原有名称/数字提取、新实体检测及十维语义审查仍执行。该设计不能用于任意重写模式，也不能把编号绑定当作事实摘要正确性的证明。
