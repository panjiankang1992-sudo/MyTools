# 图片风格首版实现与使用方法

日期：2026-09-14。状态：已发布线上并完成代表性端到端验收；不包含 LoRA 权重加载及独立图片风格参考。

## 已实现

- 24 个内置文字风格，来自调研资源包的固定版本，包含水彩、动漫、漫画、线稿、像素、黏土、剪纸、写实摄影等。内置条目不可修改，支持复制为私有风格。
- App 风格面板提供“无风格 / 内置 / 我的风格”，显示选中风格版本和合成提示词预览。文生图和图生图都可使用。
- 私有风格支持新建、编辑、复制和删除；模板为纯文本，不执行表达式。新建由客户端 UUID 标识，编辑由 expectedVersion 防止覆盖其他会话的更新。
- 新建和同内容更新可在响应丢失后安全重试。编辑产生新版本，删除隐藏入口并保留历史。
- 账户切换清理风格列表、选中项与编辑草稿，异步回调按账户修订和请求序号拦截过期响应。
- 任务保存原始描述、完整风格快照和最终提示词；作品复用读取本账户旧任务里的风格版本，不受后续风格删除影响。
- 切换到不支持文字风格的模型时清除选择；反推模式不应用风格，反推结果回填继续创作时清除先前风格。

## 使用方法（安装并发布本版后）

### 使用内置风格

1. 工具 → AI 图片生成，选择 Krea 2，输入主体描述。
2. 打开“图片风格”，在“内置”选择一种风格。
3. 查看合成文本和总字符数；需要底稿时选择图生图并上传图片。
4. 点击生成图片。选择“无风格”即可恢复纯主体描述。

### 自定义风格

1. 打开“图片风格” → “新建风格”。
2. 输入名称，例如“淡彩水墨”。模板保留恰好一个 `{prompt}`，其余部分描述媒介、笔触、配色、光线和构图习惯。
3. 示例：`{prompt}。淡彩水墨插画，宣纸纹理，松动的毛笔线条，浅灰墨色，一点朱红，画面留白。`
4. 下方会预览主体与风格合成后的文字。点击“保存并使用”，再点击生成图片试用。
5. 从“我的风格”编辑会保存为新版本；“复制”创建独立风格；“删除”不影响旧作品。
6. 也可复制一个内置风格后修改。名称上限 80、模板上限 2000、最终提示词上限 4000 个 UTF-16 单元。

模板输入允许中文。配置键与程序标识符使用英文，内置中文名称在 App 字符串资源中维护。暂不提供 LoRA 强度、负向提示词或重绘程度滑块；当前已验收工作流的采样配置保持原值。

## 接口

网关前缀 `/api/app/v1/image-generation`，内部前缀 `/internal/v1/images`。所有者来自网关会话，不能由客户端指定。

| 请求 | 行为 |
|---|---|
| GET /styles | 内置目录与本人未删除的私有风格 |
| POST /styles/{uuid} | 新建私有风格；body 为 name、promptTemplate |
| PUT /styles/{uuid} | 创建新版本；body 增加 expectedVersion |
| DELETE /styles/{uuid} | 隐藏本人风格，重复删除同一归属对象成功 |

任务 Create 新增可选 styleId、styleVersion、styleSourceJobId。前两个必须一起给出；第三个仅用于复用本人的历史风格快照。客户端不能直接提交有效的 styleSnapshot，服务端自行解析。

示例：

```json
{
  "resourceId": "krea2-local",
  "prompt": "a cabin beside a lake",
  "mode": "TEXT_TO_IMAGE",
  "references": [],
  "size": "1024x1024",
  "count": 1,
  "seed": 42,
  "idempotencyKey": "example-style-job-001",
  "styleId": "watercolor",
  "styleVersion": 1
}
```

styleId 内置为稳定短名，私有为 UUID。普通创建可引用尚未删除风格的确定旧版本；已删除风格只能从本人原任务的快照复用。对非法模板、长度和模式返回 IMAGE_002；不可访问对象 IMAGE_004；内容或版本冲突 IMAGE_005。沿用集中错误码。

## 持久化与兼容

图片服务 Flyway V2 新增 `image_style` 与 `image_style_version`。后者每个版本只插入不覆盖。内置版本位于 classpath `styles/builtin-v1.json`，同时附带 MIT 许可和归属说明。

与调研初稿的一个实现调整：风格是图片业务配置，Executor 不需要理解风格对象。因此原始主体保留在 request.prompt，固化文本保留在 request.effectivePrompt，图片服务派发前将后者投影到现有调度参数 prompt，并移除风格业务字段。Scheduler 的 additionalProperties=false 契约保持不变，执行包 1.1.2 不修改，也不需要为纯文字合成发布新包。

幂等摘要不包含新增空字段，保证旧客户端请求可命中旧任务。图片服务先查询现有幂等任务，再解析风格，防止风格已删除导致旧请求重试失败。相同幂等键更改风格仍返回冲突。

## 发布与回退

发布组件为图片服务、Gateway 和 App。Scheduler、Executor、Comfy 和权重无需变更。先发布服务端并完成 V2 迁移，再安装 App，验证风格目录与跨账户隔离，最后执行真实生成对照。不要将当前工作区其他未发布业务变更一并打包部署。

回退时可撤下 App 风格入口与网关新接口，但**已有带风格任务仍在排队时不能直接换回旧图片 JAR**：旧版本不了解快照投影，会把多余字段发给调度器。应先停止新风格提交、排空待派发任务，或保留本版兼容投影逻辑；保留 V2 数据表与全部版本。

后续内置版本升级需保留旧目录并按 (id,version) 解析，不能就地覆盖 builtin-v1.json。LoRA 和独立图片风格参考仍按调研中的独立资源、工作流与 GPU 验收计划实施。
