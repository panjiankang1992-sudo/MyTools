# 每日新闻速报：自用版实施范围

2026-10-19 按用户反馈“不要那么复杂，这只是一个自用的消息收集、汇总、发送服务”收敛。本页是后续实施依据；旧设计保留为实现记录，不再将其全部扩展项作为个人版上线前提。

## 要交付的东西

每天收到一份可读的新闻速报：技术、国际、国内、本地四类，每类最多 20 个标题，前 10 条尽量提供有来源的详情和原文链接。技术看近七日，其余看近 24 小时；不足就显示实际数量，不凑数。本地采用执行服务的出口 IP 所在地，定位失败明确提示。

用户进一步明确：每类前十应图文并茂，报告可以按分类分邮件；采集后使用 DSH 无头分析并生成报告。接收地址以最新更正为准：`panjiankang2@h-partners.com` 和 `740578608@qq.com`。旧错误地址仅保留在已发送历史记录中，不能再用于新任务。

先跑通邮件。现有飞书适配保留，按需启用；QQ 的平台主动推送限制单独说明，不阻塞邮件使用。个人只维护一份订阅，默认北京时间 07:30；保留 owner 字段，未来需要时再扩展多用户。

## 只沿着这条主链路做事

1. **采集与预览**：选少量能稳定取得内容的新闻源，复用现有采集、去重和日报页面，先看一份真实日报。源失败时跳过并注明，不让一个站点拖住整份日报。
2. **发送与定时**：复用已有邮件服务和定时设施，配置自己的接收目标；先验证一次实际接收，再开启每日发送。同一天不重复发送，失败可查看和重试。
3. **DSH 整理与图文报告**：每类冻结最多 30 条候选、排序信号、正文证据和原图；通过 `dsh --profile headless --patch ... -` 显式加载独立技能 `skills/analyze-daily-news/SKILL.md`。先用紧凑材料跨分类合并同一事件，再用各类完整证据合并、重排并精选最多 20 条，其中前 10 条输出详情。校验每个候选恰好归入一个事件或明确列入榜外，模型不能改变来源链接和配图。
4. **分类发送**：四类分别生成邮件，前十展示配图与详情，十一至二十展示标题、简述及原文链接。原文有图时采用原图；无可用原图时根据已取得的材料绘制要点图解，显著标记“非新闻现场照片”。正文不足时显示材料提示，不生成虚构详情。图片采用 CID 内嵌，邮件正文直接阅读。每类原图预算 8 MiB，实际 MIME 邮件上限 16 MiB；超限停止并报告。
5. **使用中调整**：根据实际收到的内容调整来源、排名、详情长度和发送时间。飞书及多用户随后按实际需求补充。

用户需要关心的配置只有来源、发送时间、接收渠道和自己的接收目标。数据库、内部令牌等复用现有部署配置，不再新增配置平台或新的编排系统。

## 本轮停止扩展的内容

不再为首版增加 News 派生内容期限治理、更多容量账本、复杂审计流程、多租户运营、全套故障演练或强制七日影子验收。此前已实现的代码不做破坏性回滚；必要的超时、去重、凭据保护和失败记录继续保留。

GitHub 尚无连续七日样本时展示近期活跃仓库及可用指标，不把累计星数冒充七日新增星数，也不因此阻止整份日报使用。图文摘要复用用户指定的 DSH 及已有凭据；分析失败不冒充已生成报告。

## 个人版完成标准

- 能从实际来源生成四类日报；某类材料不足或本地定位失败时，日报说明缺口。
- 前十详情使用实际取得的内容，带来源与原文链接。
- 自己的目标能实际收到一次日报，之后按配置每天发送且不重复。
- 能查看最近日报、暂停发送，以及看到失败原因。

当前采集器、日报页、订阅与邮件/飞书适配已有实现。下一步优先处理实际来源、个人配置和一次真实邮件接收；不再以新增工程治理功能替代这条业务链路的验收。

## DSH 图文链路的运行方式

实现位于 `service/news-digest-service/scripts/`：`preview-personal.sh` 采集并导出材料，`personal_report.py` 调用 DSH 并生成报告，`send_personal_mail.py` 复用 Ubuntu MyTools SMTP 发送。每次运行使用新的输出目录，保留旧材料及发送回执。

```bash
# Java 21、Maven；采集阶段只用临时 H2，无需新的生产数据库。
NEWS_ILLUSTRATED=true bash service/news-digest-service/scripts/preview-personal.sh \
  out/news-input-RUN service/news-digest-service/examples/personal-sources.json \
  /path/to/current-region-report.json

# 已配置凭据的 DSH、Python 3.9+、Pillow 和中文字体。
python3 service/news-digest-service/scripts/personal_report.py \
  out/news-input-RUN/report-input.json out/news-report-RUN \
  --to panjiankang2@h-partners.com 740578608@qq.com

# 在 Ubuntu 的独立任务目录先校验四份清单；不带 --send 不连接 SMTP。
python3 send_personal_mail.py tech/job.json
# 确认使用相同清单后发送；其他三类同理。
sudo -n python3 send_personal_mail.py tech/job.json --send
```

`dsh-news.patch.yml` 复用 DSH 已有登录配置，关闭报告任务的文件、终端、网络及子代理工具。模型只收到公开新闻材料，不收到邮件地址或 SMTP 配置。模型输出校验候选覆盖、合并成员唯一性及代表来源归属；合并 ID 由程序根据原始事件计算。完整合并映射、排除项和排序理由保存在报告目录，固定模板负责 HTML 转义及链接、图片呈现。缺图的要点卡依赖 Pillow，Linux 使用 Noto Sans CJK，也可用 `NEWS_REPORT_FONT` 指定中文字体。

首轮已在本机和 Ubuntu 验证 DSH 无头调用成功；真实四类材料完成一次 DSH 分析。该轮新版报告与原 Outbox 渲染入口分开，当时尚未接入每日自动触发。人工补采的材料单独标记，不把一次预览补齐当作自动采集能力。

2026-10-19 首轮新版四类图文邮件向当时提供的两个地址提交，四份 SMTP 回执均为 250 / accepted。详情及限制见 [首轮验证记录](../verification/daily-news/2026-10-19-dsh-illustrated-report.md)。该轮正文有三条人工补采，一次模型 JSON 格式修正；当时未开启每日定时，也尚未确认收件箱实际到达。后续邮箱更正不改变历史回执。

## 无人值守运行入口

`build-personal-runtime.sh` 打包一个带依赖的 JAR、报告脚本、独立新闻分析技能、来源配置和既有地区探测模块，并生成逐文件摘要清单。`PersonalCollectorLauncher` 已从测试入口移到主代码；运行时通过 `PropertiesLauncher` 指定此入口，直接使用临时 H2，不启动 Spring 服务，也不需要 Maven 或新的 MySQL 账号。原 News 服务部署与网页接入仍可按原方案继续，不把个人文件任务声称为 News Outbox 生产验收。

个人配置参考 `examples/personal-runtime.json`，必须填写自己的 owner、收件人和状态目录，发送开关默认关闭。SMTP 凭据仍只由邮件子进程在 Ubuntu 内存中读取。`personal_daily.py` 提供三个动作：

```bash
# 采集、分析、生成并离线校验四份邮件；不发送。
python3 RUNTIME/scripts/personal_daily.py personal.json run
# 显式发送，另需个人配置中的 enabled=true。
python3 RUNTIME/scripts/personal_daily.py personal.json run --send
# 查询本日进度及 SMTP 回执，或立即停止后续分类发送。
python3 RUNTIME/scripts/personal_daily.py personal.json status
python3 RUNTIME/scripts/personal_daily.py personal.json disable
```

同一 owner、同一本地日期固定使用一个目录。重复触发复用原采集材料、已校验的分类分析及邮件任务；输入、原图、新闻分析技能、收件人或采集程序变化时拒绝复用当天任务。每轮 DSH 格式错误最多重生成一次，两次共用分类超时预算；重试提供具体字段、候选漏项及重复编号诊断，要求基于原始来源修复完整草稿。历次响应保留，不覆盖失败证据。中途退出后，使用 `personal_report.py --resume` 或重新运行日任务恢复已有结果。

日任务隔离各分类的模型分析失败，继续完成其他分类；一轮结束后发送所有已通过内容和 MIME 校验的分类。随后最多再恢复一轮缺少的分析和明确的临时发送失败，已完成分析不重新生成，已接受邮件不再次提交。永久 SMTP 拒绝及 unknown/inflight 不自动重发，凭据错误不触发单独恢复循环。部分完成时保存失败分类与原始回执，报告入口明确标记缺少的分类，服务返回失败状态，不能把部分完成伪装成全成功。采集、共享的跨分类合并及完整性校验仍是前置条件，失败不会绕过校验生成报告。

发送前逐封重读启停与收件配置，提交前查询原任务回执；单封邮件发送失败不阻止其他已校验分类。状态查询不触发采集、模型调用或发信。停止只能阻止后续邮件，不能撤回已被 SMTP 接受的邮件。

提供用户级 systemd service/timer 模板，默认每天北京时间 07:30。此模板不自动补发关机期间错过的日报；需要时显式运行本日日任务即可。启用前检查用户服务管理器及退出登录后的运行条件，并以实际 `list-timers` 结果核对下一次触发时间。
