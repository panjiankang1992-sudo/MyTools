# MyTools 解压工具：调研、交互与实现方案

日期：2026-09-27。本文保留原始设计目标；首期核心能力现已实现并完成模拟器验收。实际交付、与方案差异及未验收项目见 [实现与验收报告](../../verification/2026-09-27-archive-tool/README.md)。

## 交付边界

本轮实现工具入口清理与二维码生成、扫码、图片识别、复制、PNG 导出。工具页面保留三列小图标：下载工具、PDF 工具、图片生成、视频生成、二维码、文件传输、解压工具。删除指定的八个无用入口，不删除其他页面仍使用的底层服务。

解压工具本轮交付本方案和 `prototype.html` 交互设计；下一轮据此实现。功能聚焦解压，不提供创建压缩包入口。

## 主流工具调研

| 产品 | 官方资料确认的做法 | MyTools 的设计选择 |
|---|---|---|
| 7-Zip | 支持 ZIP、7z、TAR 等，RAR 只解包；ZIP、7z 支持 AES-256 | 选完整 C++ 解码引擎为候选，不能只用 LZMA SDK 代替完整格式支持 |
| Bandizip | 密码管理器可自动轮询已保存密码；官方特别提示 RAR 校验可能需要完成解压，耗时较高 | 实现历史密码自动匹配，提供取消、尝试计数与耗时提示，不能把密码检测当成恒定耗时操作 |
| PeaZip | 可先浏览再解压，支持 ZIP/7z/RAR 加密；文件名加密与内容加密不同 | 未加密目录先预览；加密目录先解锁，再显示文件清单；全部/选中解压 |

官方来源（检索日期同上）：
- [7-Zip 功能与许可证](https://www.7-zip.org/)
- [7-Zip FAQ](https://www.7-zip.org/faq.html)
- [Bandizip 自动密码](https://en.bandisoft.com/bandizip.mac/help/how-to-use-auto-password/)
- [Bandizip 密码管理](https://en.bandisoft.com/bandizip/help/how-to-use-password-manager/)
- [PeaZip 加密格式与解压交互](https://peazip.github.io/extract-encrypted-files)

以上是公开功能调研，不等于 HarmonyOS 移植验证。下述架构为本项目建议。Bandizip 的自动密码与主密码限制不照搬；MyTools 使用系统安全存储保护历史密码。

## 功能与格式范围

首期目标：ZIP（ZipCrypto、WinZip AES）、7z（AES、加密文件名）、RAR4/5（读取解压）、TAR/TAR.GZ/TGZ/GZIP。格式必须通过真实样本测试后逐项声明可用；不将“识别扩展名”等同于“支持加密”。压缩包按文件头识别。GZIP 单流解成单文件，TGZ 继续识别 TAR。

支持文件选择、文件树预览、名称搜索、全选/部分选择、输出位置、冲突处理、进度/取消、结果文件打开与导出、任务记录、历史密码管理。分卷、超大 solid 包、嵌套包递归处理列入第二期；首期检测到分卷要明确提示，不显示密码错误。不要自动递归展开嵌套压缩包，不支持创建压缩包、密码暴力枚举或自动删除源文件。

## 页面设计

见 `prototype.html`，可切换预览、密码匹配、完成及密码管理状态。视觉沿用浅灰绿底、白卡、绿色主按钮，三列小图标。交互原型数据为演示数据。

1. 空态：页头“解压工具”，右侧“密码库”；主操作“选择压缩文件”，说明支持格式。
2. 已选择：文件名、压缩大小、格式、是否加密；目录树带复选框；搜索；“解压到”默认同名文件夹；显示预计大小（未知时明确未知）。
3. 密码面板：默认开启“自动尝试历史密码”；手动输入优先；说明“使用过的密码会加密保存在本机”；显示“正在尝试 3 / 18”，密码永不出现在进度中。
4. 匹配失败：保留文件选择与输出位置，提示手动补充密码；损坏或不支持的算法另列原因。超出时间预算进入暂停状态，可以继续，不能错误地宣称全部密码无效。
5. 解压中：总体字节、当前文件、取消；取消后清除临时内容，保留源文件。
6. 完成：成功/失败数量、输出总大小、目标路径；打开文件夹、导出文件；部分失败明确标注，不能显示全部成功。
7. 密码库：默认掩码，显示最近使用、成功次数、未验证/曾成功；支持单条删除、清空和用户主动查看。查看使用系统本地认证；库锁定时允许本次手动解压，但明确提示未保存并提供解锁后重试。

## 历史密码规则

记录所有实际提交给解压器的非空密码，包括未验证成功的密码；单纯输入后取消不记录。保留首尾空格和大小写，禁止 trim。相同密码去重，更新次数。默认自动保存并明确告知，提供删除管理。

匹配顺序：本次手动输入 → 当前压缩包曾成功密码 → 最近成功历史 → 其他使用过的历史。每个任务对历史库取快照，每条候选至多尝试一次，全部失败后等待新密码；不能无限循环。密码匹配成功后仍需完成所选文件的 CRC/认证校验才能标记任务成功。目录可读取不等于内容密码正确；混合密码 ZIP 按条目继续匹配。RAR/solid 包可能需大量解码才能验证，提供当前耗时，不承诺秒级。

建议每 30 秒自动暂停候选轮询并允许继续；文件解码期间也应响应取消。已尝试的候选不因继续操作再次轮询。进程退出后不持久化明文密码，重新取库构造队列。

## 实现架构

优先本机解压，文件和密码不上传后端。当前需求无需新增后端服务；若未来需要远程解压/MCP，单独设计账户隔离、临时上传和密码保管协议，不复用客户端密码库到服务器。

ArkUI `ArchivePage` → `ArchiveJobService` → Worker / N-API `ArchiveEngine` → 7-Zip C++ 解码模块。复用现有 `ArchiveTool` 的导出和路径验证经验；现有 zlib 普通 ZIP 路径保留为兼容实现，不假装支持密码。

引擎候选比较：系统 zlib 接入成本低但当前接口无密码能力；libarchive 可作为候选，但不能凭格式列表假设加密 RAR/7z 全支持；完整 7-Zip 引擎覆盖面更符合需求，须先完成 arm64 和模拟器 ABI 编译、加密格式样本试验、内存/取消验证。固定源码版本与校验值，审阅 LGPL/BSD/unRAR 条款，随包提供许可证与所需源码获取方式。此为工程评估，不代表移植已完成。

N-API 接口建议：
- `inspect(sourceFd, passwordId?) -> ArchiveInfo`：格式、加密状态、目录、条目 ID、大小。
- `extract(jobId, entryIds, targetFd, candidateHandle, limits) -> async events`：进度、需密码、完成、错误。
- `cancel(jobId)`：原子取消标记；原生读写与解码回调检查。

密码只经受控进程内句柄读取，禁止命令行、日志、崩溃附加信息携带明文。FD 必须由任务持有至原生调用完成，跨线程关闭需同步。成功与取消只完成一次，页面退出不遗留 UI 回调。

## 数据设计与安全存储

`ArchiveJob`：id、sourceUri、fingerprint、state、selectedEntryIds、outputUri、bytesDone、bytesTotal、createdAt、errorCode。任务数据库不包含密码。

`PasswordRecord`：opaqueId、secret、createdAt、lastUsedAt、attemptCount、successCount、lastSuccessAt。所有记录（包含元数据）保存在 HarmonyOS Asset Store 的独立业务命名空间。采用逐条记录与分页索引，不能无限增长为单个 64KB 条目；实现前核实当前 SDK 限额。认证凭据与解压密码使用不同别名。去重在解锁后的内存中按原文比较，避免将可离线猜测的裸密码哈希写入数据库。关闭页面/后台锁定时清理可控内存；不承诺 JavaScript 字符串可可靠擦除。

包指纹到密码 ID 的关联仅本机保存，重安装、换设备不默认同步。保存失败必须显式反馈；不得显示“已保存”。删除密码同时删除关联索引。后台及多账户切换锁定库，任务不得跨账户复用密码。

## 解压边界与错误处理

沿用保守首期限额：5000 条目、展开总量 300MiB；额度在预检与流式写出时双重执行。更大包另行增加可配置策略并做内存测试。配额按实际输出字节，拒绝虚假元数据绕过。预估检查可用磁盘空间，但写入期间仍处理空间不足。

拒绝绝对路径、`..`、盘符、UNC、NUL、符号链接及硬链接；规范化后再次确认每条路径位于独立沙箱目录。处理大小写/Unicode 同名冲突，默认重命名，不静默覆盖。临时目录隔离任务，全部校验完成后才发布至用户目录。导出失败清理本任务生成的部分文件，不能删除用户原文件。权限失效需重新选择位置。

错误码建议统一 `ARCHIVE_001` 至 `ARCHIVE_012`：格式不支持、需要密码、密码不匹配、数据损坏或校验失败、分卷缺失、配额超限、磁盘不足、目标权限失效、非法路径、用户取消、引擎失败、密码保存失败。无法区分密码与损坏时如实标注“密码或数据校验失败”。

## 实施与验收顺序

1. 原生引擎可行性：ZIP/7z/RAR 加密样本、ABI、取消、许可证，失败则重新选型，不进入 UI 假实现。
2. 数据层：安全密码库、去重、全部使用记录、排序、单条删除、异常恢复。
3. 业务层：预览、历史轮询、任务状态机、限额、路径隔离、输出发布。
4. UI：按原型落地，接入文件选择和文件管理；普通 ZIP 回归。
5. 模拟器与真机验收：空密码、正确/错误/中文/含空格密码；历史全部失败/首条命中/末条命中；ZIP 混合密码；加密目录；RAR4/5；损坏包、缺分卷、重复路径、路径穿越、符号链接、解压炸弹；取消、后台、进程终止、存储满、权限撤销。
6. 验收证据记录输入文件 SHA-256、输出摘要、用时、峰值内存及状态；删除所有合成测试压缩包、测试解压目录与测试密码，保留报告，不操作用户真实文件。

二维码验收：空输入、中文、超字节上限；生成后修改输入清除旧图；PNG 可读取；生成→导出→图片识别→复制结果完整一致；取消选择器、无二维码图片、退出过程中回调，不自动打开二维码链接。
