# MyTools 新闻 RSS 对外订阅方案

日期：2026-11-01，2026-11-02 增补 Outlook 兼容入口。按最新要求调整为**一条新闻一个条目，每条都有详情**。运行包 `1.5.1`；实际配置与恢复命令见[运行说明](../operations/news-rss.md)。原 `1.3.0` 分类日报模式仅作为兼容选项和网页归档保留。

## 目标与选择

MyTools 提供 RSS 服务，读者通过自己的阅读器订阅，无需注册账号。每天复用既有采集、正文补全和 DSH 合并结果，补齐单篇详情后生成静态 RSS、网页与图片，由既有 HTTPS/Nginx 入口提供。无需新增数据库、消息队列或阅读器服务器。

采用 RSS 2.0，`description` 提供摘要，`content:encoded` 提供该条新闻的完整 HTML 内容。[RSS 规范](https://www.rssboard.org/rss-specification)、[HTML 正文扩展](https://www.rssboard.org/rss-profile#namespace-elements-content-encoded)。提供 OPML 批量导入分类；RSSHub 等上游转换工具、FreshRSS 等阅读端不属于本次发布链路。

## 阅读方式

| 地址（前缀 `https://toolbox.yuyutian.top/news`） | 内容 |
| --- | --- |
| `/rss/daily.xml` | 全部分类的独立新闻文章 |
| `/rss/outlook.xml` | 经典 Outlook 兼容入口，最新最多 100 条且不超过 512 KiB，每条完整图文放在标准 description 字段 |
| `/rss/tech.xml` | 技术新闻，来自已有技术周榜候选 |
| `/rss/world.xml` | 国际新闻 |
| `/rss/domestic.xml` | 国内新闻 |
| `/rss/local/cn-js.xml` | 江苏本地新闻，地区由服务执行 IP 决定 |
| `/rss/trending.xml`、`/rss/military.xml` | 流行与军事 |
| `/rss/finance.xml`、`/rss/society.xml` | 财经与社会 |
| `/rss/sports.xml`、`/rss/entertainment.xml` | 体育与娱乐 |
| `/rss/categories.opml` | 已发布分类的订阅清单 |
| `/subscribe/` | 订阅地址、独立文章列表、日报归档 |

每条新闻包含标题、事实摘要、要点、来源链接和必要的材料限制。优先保留原文配图、图注和来源链接；前十名没有可用原图时使用明确标识的要点图解。后十名已有原图也展示，且必须有正文详情。信息不足不凑数，不发布“正文未获取”占位条目。读者可逐条标记已读、收藏或打开独立网页。

沿用原地址，按用户要求将 Feed 内容从分类日报切换为独立新闻。旧阅读器已保存的日报不会被主动删除；新文章使用独立 GUID 命名空间。全部新闻与分类源按需二选一，OPML 不包含全部新闻源，避免重复导入。

## 数据链路

```mermaid
flowchart LR
    A[既有采集与正文补全] --> B[DSH 每日合并与排序]
    B --> C[冻结日报]
    C --> D[既有邮件处理]
    C --> E[复用详情或 DSH 补充简述]
    E --> F[公开字段筛选与独立文章]
    F --> G[RSS 网页 配图 OPML]
    G --> H[完整快照原子发布]
    H --> I[读者的 RSS 阅读器]
```

公开访问仅下载静态成品，不触发采集、模型调用或邮件发送。RSS 与邮件结果独立记录，已准备邮件先投递，避免详情补充拖延邮件。

## 详情技能

新增 `skills/analyze-rss-articles/SKILL.md`，由 `rss_article_details.py` 调用 DSH 无头执行。每批最多 10 条，输入包含固定身份、原文证据、既有简述和原发布时间。新闻材料是不可信数据，技能要求只分析输入，不调用工具、联网或发送消息。

输出严格覆盖全部输入 ID：`ready` 需有摘要与 1—3 个事实要点；`insufficient` 需说明材料缺口，不生成臆测正文。已有合格详情直接复用。只有标题或少于 80 字符实质材料的条目不调用模型补写。

详情副本和缓存保存在每日报告旁的 `rss-articles/`，按技能与输入哈希隔离，不修改原日报或邮件任务。格式错误可在原预算内修复一次；总预算 900 秒、每批最多 300 秒；中断可继续已完成缓存。旧报告第 11—20 名只含简述的问题由此补齐，不必重跑整条日报。

## 稳定身份和历史

- 单篇身份取规范化主来源 URL 的 SHA-256；去除 fragment 和常见跟踪参数，保留有意义的查询参数。
- GUID 为 `urn:mytools:news:article:<sha256>`。同一原文多日入榜只出现一次，标题、名次和详情修订不改变 GUID。
- 不同网址的跨日同事件识别暂不新增服务；每日已有 DSH 聚类继续合并当日转载来源。不能把 URL 去重描述为全量语义去重。
- `pubDate` 是该新闻实际首次公开时间，修改内容保留它；来源发布时间不冒充公开时间。
- 网页 `articles/<sha256>/rN.html` 为不可变修订，`index.html` 为最新副本。每日分类汇总仍在 `editions/` 归档。
- Feed 按报告时区保留按报告时区计算的最近 7 天，文章网页保留 90 日；同一原文最近再次入榜会延长保留窗口。
- 单 Feed 默认 4 MiB，十分类生产配置为 8 MiB；超限保留原版本并报错，不静默删除一周内文章或剥离详情。

## 公开内容边界

仅导出标题、总结、要点、来源和新闻配图。收件人、owner/node、原始 IP、抓取证据全文、模型原始响应、邮件任务及回执不进入站点。

文本先 HTML 转义，再交给 XML 序列化。来源仅接受已校验 HTTP/HTTPS 地址。配图优先读取冻结采集包中的新闻原图，核对来源属于当前新闻或已合并来源，并验证路径、实际格式、文件大小和像素尺寸；JPEG、PNG、GIF 原字节按内容哈希托管，保留原文来源与图注。前十名缺少可用原图时才生成要点图解，明确标注非现场照片。邮件的 `cid:` 地址不进入公开正文。

完整站点与私有 manifest 同时写入一个 release；`current` 只指向其 `site/`。临时目录校验后原子切换，最近三个快照可快速回退。Nginx 只允许受控路径的 GET/HEAD，支持 ETag、Last-Modified 与条件请求；内部文件即使误入目录也不能直接下载。

## 2026-11-02 分类与标题扩展

逐条 RSS 标题统一为 `【分类】【YYYY/MM/DD】新闻标题`，日期来自该条新闻所属的报告日，不伪称新闻事件发生时间。原始标题、GUID、首次发布时间和正文不因前缀变化而重建；已有分类/日期前缀会去重。所有主源、分类源和 Outlook 兼容源规则一致。

在技术、国际、国内、本地之外新增流行、军事、财经、社会、体育、娱乐。流行采用百度公开热榜的摘要、热度与配图，不把单平台指数称作全网统计，不把采样时间填作新闻发布时间；未知日期保留为空，排序窗口单独采用观测时间。军事采用央视军事公开列表及明确发布时间，其他新分类采用中新网相应 RSS。每类最多 30 候选，DSH 跨分类去重后最多 20 条；事实不足不强凑详情或条数。

Outlook 兼容总源继续最多 100 条，保证客户端已验证的订阅方式。需要完整十分类一周内容的读者使用 daily.xml 或分类源。MyTools 阅读器同步扩展为 2,000 条/8 MiB，保留超限失败和旧数据保护。
