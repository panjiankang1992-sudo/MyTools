## 2. 已复现的离线证据

- 完整发布组装成功：14 个 Java 服务、7 个 Python 服务、117 个任务包、482 个带摘要的发布文件。
- 发布包 `operator-tools/` 包含 V3 POC、预检、黄金集评测器和质量证明签发器；三个工具可直接从发布包加载其依赖并显示帮助。
- V3 POC 需要两项显式外部调用确认、受限试读文本、私有音频/报告输出、MP3+正时长校验；没有配置 `FFPROBE_BINARY` 或输出目标冲突时不发送供应商请求。
- 黄金集评分报告和多角色门禁证明均以原子 `0600` 文件输出，不记录正文、路径、供应商密钥或用户标识。

离线测试只能证明契约和失败保护，不能证明供应商账户、真实模型质量、存储/票据配置或真机播放。

## 3. 上线前的最小证据批次

1. 由内容权利人提供不超过 900 UTF-8 字节的无敏感试读文本，并书面确认该文本可发送给供应商；由部署操作者明确授权一次隔离 V3 POC。
2. 在受限主机运行发布包中的预检和 V3 POC，保存 `AUDIOBOOK_TTS_V3_POC_V1` 报告；确认输出音频可播放、时长为正、成本与供应商控制台一致。
3. 用拥有处理权的样书跑一代单旁白整书，导出 ZIP，在真机连续播放十章并记录自动下一章、断点恢复与失败章不跳过行为。
4. 产出黄金集、NER 验收和跨章节人工复核三类记录；使用签发器生成多角色质量证明。只有全部通过后，才由变更审批开启多角色音色。
5. 在小范围所有者灰度中完成预算拒绝、Provider `429`、存储发布失败、取消/恢复及告警演练；核对 Provider 账单后再扩大范围。

## 4. 明确禁止的捷径

- 不因代码测试通过而开启 `AUDIOBOOK_MULTI_CHARACTER_ENABLED`。
- 不将凭证、试读文本、样书正文、生成音频、票据或 POC/质量门禁证据放入 Git、发布包、Scheduler 参数、App 状态或日志。
- 不在未确认内容处理权或未获外部调用授权时执行 V3 POC。
- 不跳过紧邻的 `PENDING` 或 `FAILED` 章节来伪造连续播放成功。
