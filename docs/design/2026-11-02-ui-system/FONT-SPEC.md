# MyTools 固定字体规范 · 1.1

状态：已获批准；客户端已打包同源静态400/500/600字体并在首屏前注册。目标：不同手机显示相同的UI字形、字重与基准行高。

## 字体与真实资源

统一采用 Noto Sans SC。中文、拉丁字母、数字采用同一字体家族，主字体不引用手机系统或主题字体。评审稿通过本地 `@font-face` 加载 `assets/fonts/NotoSansSC-Variable.ttf`；不依赖在线字体服务或已安装字体。字体为100–900可变字重源，常用400、500、600。

官方来源：[Google Fonts字体目录](https://github.com/google/fonts/tree/main/ofl/notosanssc)、[元数据](https://github.com/google/fonts/blob/main/ofl/notosanssc/METADATA.pb)、[Noto CJK格式说明](https://github.com/notofonts/noto-cjk/blob/main/Sans/README.md)。字体授权SIL OFL 1.1，完整许可证在 `assets/fonts/OFL.txt`。分发时保留版权与许可证，字体不得单独销售。

当前完整源文件17,772,300字节，SHA-256：`a3041811a78c361b1de50f953c805e0244951c21c5bd412f7232ef0d899af0da`。版本固定依赖资源文件与哈希，不因设备安装字体或字体服务更新而变化。

## 客户端实施要求

1. 从应用rawfile注册独立的MyTools字体家族，并由主题和公共组件显式使用；仅写 `.fontFamily('HarmonyOS Sans')` 仍是引用系统字体，不能满足本要求。实际API按项目SDK验证，[OpenHarmony字体注册文档](https://raw.githubusercontent.com/openharmony/docs/OpenHarmony-5.0.0-Release/zh-cn/application-dev/reference/apis-arkui/js-apis-font.md)提供rawfile注册方式。
2. 优先验证同源可变字体的400/500/600渲染与内存占用；若目标系统的字重映射不可靠，则从同一源生成静态400/500/600资源并分别注册，不靠字体加粗模拟。
3. 固定UI不跟随手机主题字体；仍支持系统字号放大。阅读正文默认使用同源字体，读者在阅读设置里主动选择的字体按既有阅读偏好生效。
4. 内嵌可控网页与原生壳使用同源文件；上游不可控区域登记例外。图标继续使用图形资源，不用系统图标字符或emoji冒充固定图标。
5. 完整中文字体体积较大，实施时核对包体、首屏排版、读取耗时和内存。可将固定UI文案做子集并离线随包分发；动态书名、文件名、RSS与正文仍需完整字形覆盖。不能仅按14张样稿中的汉字生成生产字体。
6. 缺字只对该字符回退，记录并补齐字体覆盖；生僻字符、其他文字与emoji允许专门回退。主UI中文、英文与数字不得因字体未注册而静默整体切回系统字体。

## 验收

- 在不同主题字体的设备上比对相同UI文案，字形/字重/换行一致；不同屏宽和字号缩放按设计规则适配。字体渲染器差异不要求每个像素完全相同。
- 检查汉字、标点、拉丁字母、数字、长文件名、繁体/生僻字与emoji；固定字体覆盖范围和回退字符可定位。
- 检查400/500/600确实使用对应字重，200%字号不裁切，按钮命中区域不重叠。
- 冷启动、无网、重启均可使用本地字体；不把字体网络下载加入打开图书的链路。

客户端使用 `rawfile/fonts/NotoSansSC-{Regular,Medium,Semibold}.ttf`，通过 `AppFonts.register` 注册独立家族；共31,770,524字节，含完整动态中文覆盖及OFL许可证，哈希记录在同目录 `SOURCE.json`。真实字重分别为400/500/600，不通过伪粗生成。真机及多机显示对照待设备连接后完成，详见实施记录。
