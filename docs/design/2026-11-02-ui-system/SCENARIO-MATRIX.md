# 页面场景与组件覆盖矩阵 · 1.2

目标是按实际任务提取控件与组合组件。单个页面可以复用多项基础组件；不会为了增加组件数量把每个业务字段都复制成新组件。当前代码证据见 `CONTROL-COVERAGE.md`，组件逐项规范见 `COMPONENT-SPEC.md`，交互边界见 `STATE-MATRIX.md`。

本矩阵描述设计覆盖，不表示已修改客户端。日期/时间等在客户端未发现的能力作为规范补齐，不据此增加业务入口。

## 组合规则

1. 搜索框负责输入，搜索按钮负责提交，搜索建议负责候选，搜索结果由列表/卡片/空错误状态承载。不能用一个组件包办所有数据请求。
2. 下拉字段负责触发与当前值；短列表使用选择面板；大列表复用搜索、虚拟列表、加载/空/错误状态；多选与级联有独立规范。
3. 表单组负责标签、帮助、必填、错误摘要与提交时机；各字段保留自己的值和校验规则。错误摘要定位到字段，不能只显示一条Toast。
4. 文件选择器、上传队列、文件行、预览和任务状态分工明确；系统文件/相册授权界面作为平台组件登记，不伪装为自绘系统界面。
5. 通用表格、日期、评级等用于具备对应业务的平台或预留规范。未发现原生使用证据的项目，在实施清单里标记“规范补齐”，不能默认为本次新增功能。
6. 协议同意、隐私、退出、清除、删除等沿用现有保护语义；组件规范描述其样式与交互，不扩展权限或改变业务影响。

## 迁移完成的判断

按代码调用点和页面任务双向核对：每个现有控件映射到组件ID或登记例外；每个可达页面在矩阵中有对应任务。仅列出72个名字或只改公共按钮不能作为全量完成依据。
