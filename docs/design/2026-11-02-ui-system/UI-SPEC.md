# MyTools 统一 UI 组件规范与设计要求

版本：1.4（审核通过后的客户端实施版，2026-11-03 补充输入行规则）。初版日期：2026-11-02。状态：用户已明确批准，鸿蒙客户端正在完成构建与验收；实施记录见 `../../verification/2026-11-02-ui-system/IMPLEMENTATION.md`。

范围：本轮的页面优化主体是 MyTools 鸿蒙客户端，含原生页与 DSH 内嵌页的衔接。完整组件规范覆盖跨端可复用控件；代码盘点附带记录网页已有场景，网页不因此自动进入实施范围。后台管理 Web、公共工具网站的全量改造需另行纳入实施清单。设计稿在 `index.html`，设计变量在 `tokens.json`。

## 1. 设计目标与边界

让用户快速分辨“在哪里”“下一步做什么”“还有哪些操作”“当前是什么状态”。覆盖动作、输入、搜索、选择、日期时间、数值、导航、数据展示、反馈、弹层和业务组合，统一字号、尺寸、圆角、颜色、点击面积与状态行为。

保留现有青绿品牌识别、五个一级入口（阅读、工具、DSH、多媒体、网盘）、业务功能与用户数据。书架/书源/远程/本地/RSS 保持同级；封面进详情、文字区进阅读；离线缓存状态继续可见。阅读主题与媒体沉浸界面具有独立语义，不机械套用白底表单样式。

用户已在聊天中明确“开始改造”，本轮据此实施现有鸿蒙客户端页面和公共组件。72项目录中尚无业务场景的日期、评分等条目仍作为规范和样例，不凭空新增产品功能。

## 3. 视觉基础

方向：低装饰、清晰的青绿工具界面。利用对齐、间距、文字层级和细分隔组织内容；阴影只服务悬浮层，不给普通行或按钮普遍添加阴影。主按钮使用纯色；玻璃模糊可保留在必要的沉浸覆盖层，普通表单与列表不依赖模糊效果。

### 色彩

| 语义 | 浅色 | 深色 |
| --- | --- | --- |
| 页面背景 | `#F5F7F5` | `#101815` |
| 内容表面 | `#FFFFFF` | `#19231E` |
| 次表面 | `#EDF2EE` | `#223029` |
| 主操作/可点击文字 | `#087E61` | `#66D6AC` |
| 主按钮文字 | `#FFFFFF` | `#10271E` |
| 选中弱底 | `#E3F2EB` | `#233D31` |
| 主文字 | `#1C2922` | `#EFF6F0` |
| 辅助文字 | `#52655B` | `#AFBDB5` |
| 浅色次三级文字 | `#65736B` | 复用辅助文字 |
| 分隔/边界 | `#D5DED7` | `#3A4C41` |
| 危险文字 | `#B83D37` | `#FF9D93` |

浅色主按钮白字约 5.04:1；三级文字与白色约 4.98:1。项目目标：普通必要文字至少 4.5:1；对有意义的控件边界/图标单独核对相邻色，不用“整体过关”替代逐项检查。参考 [W3C 文字对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum)。这是设计验收目标，并非宣称原生应用已符合 WCAG。

不要用主色展示所有静态标签；不要只用红绿表达成功/失败，必须配文字或图标。占位符不能取代输入标签。

### 字体、尺寸、间距

| 用途 | 字号 / 行高 | 字重 |
| --- | --- | --- |
| 一级页标题 | 26 / 34 | 600 |
| 深层页标题 | 20 / 28 | 600 |
| 分组标题 | 18 / 26 | 600 |
| 列表标题 | 16 / 24 | 500–600 |
| 正文 | 15 / 24 | 400 |
| 表单字段值 | 16 / 24 | 400 |
| 按钮文字 | 16 / 22 | 500；主按钮600 |
| 说明 | 12 / 18 | 400 |

客户端字号用 fp、布局用 vp；HTML 样稿的 CSS px 仅用于视觉评审，不是单位换算依据。UI 使用随应用打包的 Noto Sans SC，不通过系统字体名称解析，也不跟随手机主题字体。固定字形与字重，同时保留系统字号缩放；尺寸均为最小值，避免切掉大字号文字。正文400、文字操作500、主操作和标题600，禁止伪粗与人为压窄字形。阅读正文默认同源字体，读者主动选择的阅读专用字体独立生效。详见 `FONT-SPEC.md`。

间距刻度：4、8、12、16、20、24、32、40、48。页面水平边距 20；卡片内边距 16；元素间距 8/12；分组间距 24；普通按钮圆角 10、卡片 16、底部面板 24、筛选胶囊 999。

## 4. 按钮组件族——核心规范

建议组件：`AppButton`、`AppTextAction`、`AppIconButton`。旧 `AppPrimaryPillButton/SecondaryPillButton/DangerPillButton` 可先作为兼容包装，调用新组件；随后按场景逐批迁移。

### 角色与尺寸

| 角色 | 常用文字 | 默认尺寸 | 外观与规则 |
| --- | --- | --- | --- |
| Primary | 保存、开始生成、继续阅读、上传文件 | 底板可见高40、点击高44；左右14；16/22 SemiBold | 主色纯底；一个当前任务区原则上一个主动作；不把刷新/取消设为主按钮 |
| Secondary | 查看目录、选择文件、预览结果 | 单独可见高36、点击高44；左右14；16/22 Medium | 中性色边框、表面底；成组改用原生分组按钮，底板与命中统一至少44高 |
| TextAction | 管理、刷新、复制、编辑、挑选风格 | 点击区最小44高；左右8；16/22 Medium | 常态无底色和边框；有按下反馈。不是可点击的普通 Text |
| IconButton | 返回、搜索、更多、关闭 | 44×44，图标 20–24 | 禁止仅靠图标图形命名；需 accessibilityText，状态与点击区域一致 |
| Danger quiet | 移出书架、删除、清除 | 弱底可见36、点击44；16/22 Medium | 放管理分组/菜单，使用危险文字或弱底；不与阅读/下载主动作并排高亮 |
| Danger confirm | 删除文件、清除缓存 | 可见40、点击44；16/22 SemiBold | 只在确认层中用危险实色；文案明确对象与影响 |

本项目采用 44 vp 最小可点击区域作为统一触摸目标；这是项目目标，不把 CSS 像素标准等同于原生 vp。底板或描边收进真实按钮边界，主按钮上下各2、次按钮各4；不是用额外悬浮热区覆盖邻居。紧凑外形不缩小命中区。筛选标签视觉高30、字号14，外部真实命中容器高44，且命中区不得互相重叠。

### 输入行与会话输入

独立动作继续使用主底板40、次底板36、命中44的紧凑尺寸。按钮与输入框组成同一行时改用 `fieldAligned: true`：可见底板与真实命中区均至少48高、12圆角、上下内缩为0。不得只对外层指定48高而保留内部2/4的透明留边，也不得把普通输入行按钮做成图标32高的弱底。

- 搜索、创建分组、数值字段旁动作等单行组合，共用同一最小行高；字体或标签需要增高时须由父容器显式提供共同高度，不能只拉伸透明命中区，也不能把原生Stretch当成自动等高保证。
- 输入值、提示文字与占位文字均使用打包的 Noto Sans SC；`TextInput`、`TextArea` 的 `placeholderFont` 必须显式指定本地家族，占位字号与输入值一致，不随手机主题字体改变字形。
- 下载会话的加号、粘贴、发送采用48高基准。保留系统 `PasteButton` 的授权机制，只统一其48高与12圆角，不用普通按钮代替。
- 下载输入框在空白与单行状态为48高；长消息可以增高至128，超过上限由输入框内部滚动。多行时动作仍保持48高并与输入框底部对齐，不把加号、粘贴、发送拉成128高的大按钮。
- 下载输入区按组件实际可用宽度适配：不足360vp时，附件与编辑器一行，粘贴与发送在下一行靠右；每行保持48高基准，避免挤压输入框导致占位文字竖排。宽度变化保留同一编辑器和草稿。
- 内容列表、菜单与带多行说明的行使用 `minHeight`；长文案和大字可增高或换行，不用固定 `height` 裁切文字。

### 成组操作

确认/取消、保存/取消等成组动作使用 `AppGroupedButton`：可见底板与真实命中区同框，最小44高、间距8、圆角10、左右内边距12，文字统一16/22、500字重。非满宽双按钮组以200总宽为上限（96×2＋8），可用父宽更小时继续等分缩小；各按钮默认不设置固定最小宽，以父级等分宽度为准，文字可以换行。主次通过颜色与边框表达，加载保持组宽。普通工具栏里的独立文字操作不强制等宽。

`AppGroupedButton` 只有一个原生 Button 根节点，不覆盖 `onMeasureSize/onPlaceChildren`。成组父级统一使用 `AppEqualActionRow`，先按当前可用宽度扣除间距后等分，第一遍测量所有动作的自然高度，取最大值向上取整并限制在父级边界内，第二遍把相同精确高度传给每个动作。放置时按实际子节点数量依次排列，不假设固定索引、不包裹额外Flex，也不在布局回调中写组件状态。字段同行需要48基准时设置行的 `rowMinHeight` 和动作的 `fieldAligned`。

兼容的三个 Pill 包装器在 `grouped: true` 时转交 `AppGroupedButton`，非分组分支仍使用紧凑按钮。旧 `AppButton.grouped` 参数继续保留兼容，但原生Flex Stretch与自定义按钮测量均不能单独保障自动高度行的可见底板等高。共享容器内部用稳定单项ForEach虚节点闭合构建器，确保末尾自定义按钮也进入原生测量列表。实际组必须在真机或原生模拟器确认按钮数量、长标签换行后的等高和状态更新；大字号单独记录覆盖范围，不能只靠模拟约束通过就宣称完成。

### 文字按钮的精确要求

- 同一层工具栏统一16 fp、Medium 500、22 fp基准行高，左右8 vp，最小点击高44 vp；按下反馈弱底高32。带图标间距6 vp，图标18–20 vp。
- 对齐整组的文字基线；不要让“编辑/刷新/删除”分别继承系统 Button 默认 padding。
- 一行最多展示 2–3 个常用文字操作；其余进入“更多”。不得通过把字号压到 10–12 来硬塞。
- 文案采用动词加明确对象，优先 2–6 个汉字。可直接理解时使用“复制/刷新”；含混的“确定”改为“删除文件/保存设置”。
- 超长标签不截掉动作动词；宽屏可自适应，窄屏改整行或允许两行且增加高度。同组双按钮在大字下可纵向排列。
- “已缓存/同步完成/第 28 章”是状态文本，不能使用按钮弱底让人误以为可点击。需要管理时给独立“管理”操作。
- 静态页面说明不使用主色伪装链接；真正外部链接应有可访问链接语义和清楚去向。

### 状态矩阵

| 状态 | 视觉 | 行为/可访问性 |
| --- | --- | --- |
| 默认 | 按角色 token | 支持点击与辅助设备激活 |
| 按下 | 主色变深或弱底着色；100–160ms | 不改变宽度、位置或字号；不会误触相邻项 |
| 焦点 | 2–3vp 焦点环，与控件间隔 2–3vp | 按视觉顺序移动；焦点不被底部栏遮挡 |
| 加载 | 加载图标 + “保存中…”等动作状态 | 禁止重复提交；保持可读颜色，保留宽度；不通过整体透明度模拟全部状态 |
| 禁用 | 专用禁用背景/文字 | 不响应；附近解释原因。不能让用户只能猜测为什么不能点 |
| 成功 | 图标 + “已保存”或就近提示 | 普通操作可短暂反馈后复位；读屏适度播报 |
| 失败 | 就近错误信息 + 明确重试入口 | 保留输入，不把异常信息全部挤进按钮文字 |

设计接口（具体原生接口见 `AppControls.ets` 与实施记录）：`variant`、`size`、`label`、`leadingIcon`、`enabled`、`loading`、`loadingLabel`、`fullWidth`、`grouped`、`fieldAligned`、`accessibilityText`、`onAction`。加载状态由组件阻止重复激活，业务层保留必要幂等保护。

| AppStatus / AppProgress | 状态轻量、可读，真实进度用确定式，未知进度用不定式 | 等待、处理中、已完成、失败、可重试 |
| AppSheet / AppDialog | 顶部名称和关闭；危险操作独立分组 | 打开、提交、错误、取消、键盘弹出 |
| AppEmptyState / AppErrorState | 一句说明+一个主路径；必要时一个补充路径 | 无内容、无搜索结果、未登录、离线、来源失效 |
| AppToast / AppInlineNotice | Toast 用于短反馈；长期问题用就近说明 | 成功、警告、错误、消失与读屏播报 |

分段导航与筛选不复用提交按钮的视觉语义。加载骨架不改变最终列表结构，禁止每次后台刷新闪空已有内容。无数据与网络失败要区分，不能将请求中显示为“没有内容”。

## 7. 适配与验收要求

- 手机窄宽：至少 320/360/390/412 vp；平板/横屏按已有布局能力，文本可读宽度受限而不是无限拉伸。读者设置的页边距继续生效。
- 字号：100%、130%、200%；不同手机主题字体下固定 UI 字形一致；长中文标题、英文连续长串、数字进度、4–10字按钮标签。标签不压缩到不可读，核心动作不截断。
- 交互：可点击区域至少44，回退路径明确，关闭不丢输入，加载防重入，列表滚动不触发按钮；书封面与文字区域的点击不冲突。
- 页面安全区：状态栏/底部手势区/键盘出现时，输入和主操作仍可见；不得把系统安全区硬编码进页面内容。
- 对比度：验证浅色、深色与阅读/媒体覆盖层真实相邻色；状态不只依赖颜色；禁用态仍可识别。
- 可访问性：按钮名称/状态、分段选中、输入标签/错误、焦点顺序、读屏通知。仅图片对比不算完成验收。
- 性能：不因美化增加全局持续模糊/复杂阴影；列表复用和缓存加载不退化；动效140–220ms，支持系统减少动效。
- 业务回归：阅读续读/缓存/书源、任务取消与进度、文件操作确认、会话与登录恢复都需保留；不把 UI 改造混为业务重构。

## 8. 审核项

1. 青绿品牌保持，主按钮改为深青绿纯色，减少泛用渐变/阴影。
2. 独立动作按钮10圆角；主操作可见40、次操作36，真实点击区域至少44；输入行改用 `fieldAligned` 的48最小可见/命中高与12圆角；筛选保持胶囊。
3. 动作文字16/22、真实字重500/600；固定打包Noto Sans SC，系统字号缩放保留。
4. 按72项组件样例、共享状态、20类页面任务、14张关键模板与迁移清单逐批覆盖；未发现现有使用的组件标记为规范补齐。

设计已获聊天中的明确批准。当前构建、自动回归与真机验收分别记录在实施文档，未完成的人工检查不计为通过。
