# 日报通用正文补全

## 目标与执行位置

每次日报自动为缺少正文的候选新闻补充公开材料，再让既有 DSH 新闻技能完成事件合并、排序和摘要。该能力属于正式采集流程，不依赖人工为某一天的新闻补写正文。保持现有个人服务、定时任务与四类邮件流程，不新增数据库、常驻浏览器或收费抓取服务。

执行顺序：采集和排序约 30 条候选 → 缺正文优先补全 → 下载原图 → 冻结分析输入 → DSH 跨类合并、分类精选 Top20 / Top10 图文 → 校验并发送。

## 获取策略

`ArticleContentResolver` 复用现有受限 HTTPS 传输器，按以下途径获取可验证的内容：

1. 原文 HTML：先读匹配文章身份的 JSON-LD `articleBody`，通用网页优先交给 **Trafilatura 2.3.1**。该组件只离线处理已验证 HTML，关闭评论、表格和链接输出，偏向准确提取；进程最多 10 秒，失败继续已有 HTML 提取策略。保留 README 和已有地方来源明确正文容器。去掉导航、表单、评论、推荐区和隐藏内容。
2. 无明确容器的网页：需匹配主标题、至少两个实质段落且链接占比较低，才使用段落提取。
3. GitHub 仓库：优先读取页面 README；网页未提供正文时，调用官方 README 接口。显式分支保留 `ref` 并核对返回文件分支，不猜测包含多段路径的分支/目录。
4. 页面明确声明的同站替代表示：AMP、WordPress 单篇文章 JSON、RSS/Atom。AMP 必须回指原文 canonical；WordPress `link` 和订阅条目 URL 必须匹配原文，禁止把整个订阅源拼作一篇新闻。
5. 获取结果还要过滤独立版权声明、页脚及摄影/编辑署名；过滤后仍需达到实质证据阈值，不能把这些文字计入正文补全成功率。
6. 只有页面简介可用时，标记 `META_DESCRIPTION`，保持与实际正文的区别。全部失败时保留现有来源材料；仍无事实材料的条目继续显示缺失提示，不能让模型凭标题补写。

JSON-LD 只读数据，不执行脚本；只接纳文章类型和相符身份，拒绝声明非免费访问的结构化全文。普通网页若明确声明另一篇文章的 canonical，则拒绝。身份比较允许 http/https、www 与尾部斜杠的常见显示差异，但不忽略有意义的查询参数；这些规则不放宽网络连接限制。

## 成熟组件的选择

本次采用 Trafilatura，负责 HTML 到正文的提取。实测中 GitHub 仓库页面可能被通用算法提取为登录状态提示，因此仍使用 README 容器或官方接口确认仓库材料；网络采集、替代表示身份校验和权限预算由现有 Java 链路统一管理。独立虚拟环境 `venvs/content-1.2.0` 固定组件版本，通过 `NEWS_CONTENT_PYTHON` 指定解释器。主日报进程、DSH 与邮件发送解释器保持原配置，避免为提取组件改变发送通道。

安装运行环境：

```bash
python3 -m venv ~/workspace/news-personal/venvs/content-1.2.0
~/workspace/news-personal/venvs/content-1.2.0/bin/python -m pip install -r RUNTIME/scripts/requirements-personal-report.txt
```

用户级 service 模板已设置 `NEWS_CONTENT_PYTHON`；命令行预览时使用同一环境变量。`extract_article.py` 和依赖声明进入运行包摘要清单，升级应发布新版本，不能原地修改已发布脚本。

浏览器类工具适合必须运行 JavaScript 的页面，但会新增浏览器安装、脚本子请求管理和更高资源开销。本轮先用成熟 HTML 正文提取器解决通用抽取，未启用浏览器渲染；后续可在同一解析器的失败分支添加受限浏览器适配器，而无需改变分析和邮件步骤。

## 预算、权限与结果记录

- 每篇最多 3 次请求，45 秒软截止；每次 HTTP 请求沿用 20 秒上限、压缩前后分别 2 MiB 响应上限、HTTPS 和实际 DNS 公网校验。截止前已开始的请求仍可能运行到单次超时。兼容忽略 identity 协商仍返回 gzip/deflate 的站点，解压不放宽大小和时间限制。
- 每分类先给正文最多 90 秒，再给图片最多 30 秒，总启动请求窗口 120 秒。缺正文的候选先处理；输出顺序仍按原排名。图片失败不丢弃正文。
- 一轮共享 URL 结果缓存和主机限流状态，避免重复获取或持续冲击限流站点。未发起请求的预算耗尽结果不缓存。
- 沿用来源 `EXCERPT_ALLOWED` 与证据过期检查；不为仅元数据来源获取正文。
- 原文、公开接口和订阅结果都作为不可信数据交给现有 DSH 分析流程，模型仍无网络、文件或发送工具。
- `report-input.json` 每条增加 `contentAcquisition`：状态、提取方式、实际证据 URL、获取时间、各次尝试及结果、是否选入摘要输入。分类汇总记录补全前后数量、恢复数、仍缺少数。
- 摘要证据最多保留 4,000 个 Unicode 码点，不存整站 HTML。补到的来源 URL 进入现有合并来源链接，摘要可追溯。

## 验证与部署

单元与集成测试覆盖结构化身份、无语义段落、列表 README、分支一致性、AMP/WordPress/订阅身份校验、错误页、限流、缓存、请求数量、公网 URL、权限及正文优先顺序、版权声明误提取和大响应超限后取消连接。

使用最近三天被冻结输入中的缺失条目，在独立验证目录运行正式解析器；只对新副本生成 DSH 报告，不修改既有邮件任务。验证通过后打包不可变运行版本 `1.2.0`，逐文件校验摘要，再切换每日定时服务。旧 `1.1.4` 保留供回退；当天已有输入不混用新 JAR 重新发送。

## 当前边界

动态页面仅在公开 HTML、结构化数据或已声明公开表示中含有内容时可补全。登录、验证码、付费内容、纯视频、PDF 或没有可识别正文的图集仍可能缺失；本版本不引入浏览器执行或 PDF 提取。展示缺失状态是获取结果的一部分，不能把“运行成功”解释为所有原文都能获得。

依据：[Trafilatura 官方提取接口](https://trafilatura.readthedocs.io/en/latest/corefunctions.html)、[GitHub 仓库内容与 README 官方接口](https://docs.github.com/en/rest/repos/contents#get-a-repository-readme)。真实样本与发布结果见 [验证记录](../verification/daily-news/2026-10-31-content-acquisition.md)。
