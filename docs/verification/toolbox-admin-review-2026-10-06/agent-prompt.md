## 实现顺序与完成标准

### S1：管理员会话与页面清理

- 增加安全 CSRF 恢复，浏览器刷新和多标签页都可写；不得把上游 access/refresh 暴露浏览器或存 localStorage。
- 管理页面移出公共 KeepAlive。管理缓冲绑定 userId+editionId，退出、跨标签退出、撤权、换账号销毁并取消请求；公共字帖草稿不动。
- 集中处理401/403/503：明确期限到期保留同账号缓冲，撤权清除，不可用冻结。真实页面按钮接入 canWrite。
- 按设计实现 access 尚有效时的提前刷新、实时管理员校验、session级单飞和凭据 revision CAS；不能对任意401刷新。旧请求不得误删新会话。
- logout 先验证本地 CSRF/Origin，再清本地会话，最后尽力上游注销；上游不可用也能安全退出。
- 登录成功后校验/建本地会话失败清理新上游会话；活动 touch 用条件 UPDATE，不允许与注销竞态重建旧会话，状态查询不延长空闲期限。
- 验收必须挂载真实 App/Editor 或真实浏览器，不能只测试 store 用户名。

### S2：无损草稿、稳定 ID 与校对契约

- 明确独立 AdminDraft DTO，保留教材地区/ISBN/年份/来源/缺失范围，以及条目 pinyinSegments、词性、义项、上下文、答案、sourceRefs、类别和顺序；暂不编辑的字段也必须往返保留。
- 增加显式开始编辑接口，由当前 PublishedBook 无损创建草稿。已有草稿不覆盖；GET 不隐式创建。修复迁移留下的空草稿，保留已有管理员实际编辑。
- 原完整配对导入行 initialized=true，保留已核对状态和 baseContentVersion。
- 新行创建时稳定 rowId、赋当前节点归属；首次保存事务内分配唯一正式 ID，服务端掌握映射，返回 unit/lesson/entry 三类映射。禁止数组位置分配新 ID 与旧映射碰撞。
- 前端任一侧有内容都保存；学科切换有清晰确认和无损缓冲，已发布教材身份字段锁定。
- 客户端只提交确认意图，服务端规范化、重算摘要、记录当前核对人和时间。摘要覆盖影响含义与来源的字段，修改撤销确认；发布不能冒充人工确认。
- 保存拒绝结构非法但允许内容暂缺；发布无论 partial/complete 都要求新增改动项已核对。完成 ID/引用/顺序/合法拼音/数量/来源校验，输出可定位问题。
- 用真实 760/777/140 条教材往返测试，不用新造相同行数组替代旧版本迁移场景。

### S3：可靠保存状态机

- 建独立 admin draft store/composable。约2秒防抖自动保存、手动保存、dirty/编辑代次、串行队列、未保存离开提示、冲突差异与读取最新。
- 每次操作冻结 payload/revision/idempotencyKey/editSequence/账号与页面身份；网络失败重试原操作同键同体。
- 成功响应只更新保存基线、revision和仍存在节点映射，不覆盖用户在途编辑，不复活已删行；新编辑保持dirty并排队。
- API支持指定稳定key，不能每次重试生成新key。保存/发布都按此规则。
- 慢网络、丢响应、删行、换册、换账号、409场景必须有页面组合测试。

### S4：原子发布、幂等与目录更新

- validate绑定draftRevision；publish绑定draftRevision/baseContentVersion/changeNote，幂等摘要包含完整意图。
- 固定锁顺序，锁内校验当前revision/base和分配最终contentVersion/时间；最终字节/hash/目录候选校验通过后才提交。
- 草稿/正式映射/版本/current/epoch/干净基线/审计/幂等回执处于同一业务事务。处理同键并发，回执失败不能留下无法恢复的半成功。
- 获取锁之后基于最新目录构建完整快照，不同教材同时发布不丢其中一本。
- 目录、epoch、索引、词典用同代不可变快照，词典在局部构建后整体替换，不clear正在使用的Map；翻译缓存隔离代次。
- 公开目录no-cache+epochETag。files模式未完成完整迁移时禁止发布切换数据源。
- 提交后原子交换；重载失败实际关闭教材就绪并恢复，不能只设置无人读取的ready标记。
- 注入回执/事务/快照故障和同键、同册、双册并发，验证恢复；使用隔离MySQL验证真实事务，不仅H2。
