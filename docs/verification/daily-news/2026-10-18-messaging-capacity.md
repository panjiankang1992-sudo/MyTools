# 第十九批：消息容量与取消保留额度

状态：实现、本地验证及隔离 MySQL 验证完成。持续目标 ACTIVE。

## 行为

Messaging V21 增加新目的地、普通投递、仅取消身份及冻结 JSON 字节四类有限额度。默认 1000 / 100000 / 100000 / 512 MiB，计费与业务写入共用数据库事务，多个实例争抢最后一个名额也不会超额。重复请求通过当前读核对身份，不再次扣费。容量达到限制返回 503 / MESSAGING_026，新闻服务按暂时失败保留原请求。

未知键取消使用独立保留额度，直接保存不可发送的 CANCELLED 身份摘要，不保存正文。普通消息满额不会用掉取消额度；取消额度自身也满时明确返回 503，不能宣称取消完成。已有请求的取消、停用、执行、重试和 UNKNOWN 对账无需申请新额度。严格内容摘要继续区分 null 和空 HTML，迟到创建只能重放原结果。

清理已结束正文时只归还 UTF-8 JSON 字节，原幂等身份永久保留。UNKNOWN/SENDING 保留正文与额度。数据库新增投递和尝试的 1–100 代约束及尝试父记录关联；取消身份不能转为可发送状态。管理清理接口增加只读账本核对，不暴露消息或接收地址。

V21 保守回填存量消息，旧内容和状态不变；异常历史关联或代次会阻断迁移，不能自动删除。旧写入者必须停止，回退仍需 V21 兼容应用。容量配置范围、新环境默认值、发布 JAR 迁移与类文件门禁同步。

## 验证

本批不同用例合计 **409 项通过**：Messaging 143、News 本地 210、部署工具 38、隔离 MySQL 18。News 本地报告 232 项，跳过的 22 项中 18 项在 MySQL 单独执行通过，剩余 4 项可选外网来源用例未运行。Java 21 严格编译及 Messaging 打包通过，205 个既有 SQL 迁移摘要不变。

新增本地 16 项用例覆盖额度满后的重放和停用、并发新建/同键重放、独立取消额度、取消身份不可发送、所有者和严格 HTML 身份、额度满后执行及未知结果核对/重试、代次上限、UTF-8 字节、事务回滚、正文空间复用、未知正文保护、账本差异及 503 响应。

真实 MySQL 8.4.11 的完整迁移范围为 News 9 / Messaging 21 / Scheduler 176；18 项用例均通过且无跳过。新增三项复用 Messaging 自身仓储/清理测试场景，验证 V20 存量回填、真实多连接准入/重放、取消与创建竞争；它们不是渠道送达测试。测试包 682 个文件均校验大小和 SHA-256 后执行。

隔离套件通过 `MySqlCompatibilityLauncher` 运行。除 News 编译输出、测试依赖和旧 Flyway 测试依赖外，classpath 需要 Messaging 的编译类以及 `OutboundCapacityDatabaseScenarios` 测试类；先对两个模块执行 `test-compile`。环境仍须提供私有 `NEWS_MYSQL_TEST_CONFIG`，并通过回环地址、非业务实例随机身份验证。News 生产模块未增加对 Messaging 实现的依赖。

所有临时数据库、测试和初始化单元均已停止，临时目录、传输归档及本地私有凭据目录删除。原有 Scheduler、Executor、Messaging、Gateway 服务仍为 active，未修改生产业务库或部署服务。

发布包位于 `/tmp/mytools-news-release-20261018-b19-verified`，18 个 Java 服务、7 个 Python 服务、153 个任务包、733 个文件；仅 Messaging JAR 在本批重建。完整文件、固定运行依赖、V21/容量类门禁通过，两项包内 CLI 帮助检查不修改清单。精确摘要和源码证据见 `news-messaging-capacity-test-summary.json`。
