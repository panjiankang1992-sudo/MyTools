# 每日新闻第六批验证：订阅与日报阅读页面

日期：2026-10-18。用户明确要求主动制定目标并推进；本批目标为完成现有登录前端的个人新闻订阅与阅读闭环。目标已完成工程实现与本地验证，未部署生产。

## 交付范围

- 认证路由与菜单 `/news`；复用登录客户端，经同源 `/api/v1/news` 请求 Gateway。开发代理独立于旧单体 `/api`；生产需配置同源反向代理。静态路由已登记，动态菜单模式需菜单服务提供对应定义。
- 订阅启停、时区、截止时刻、下次截止展示；版本冲突保留草稿并阻止再次覆盖，重新载入后恢复编辑。自动生成未启用与投递未接通单独说明。
- 最近 100 份历史、四分类 Top20/Top10 阅读、缺口、引用展开、GitHub 趋势质量；正文按文本渲染，拒绝危险协议和带凭据外链。历史地区不被当前地区覆盖。
- 预览请求使用服务返回 cutoff；同页面未知网络结果重试保留原键。快速切换历史和预览竞争只保留最新选择，卸载后旧响应不回写。请求随机键使用浏览器 getRandomValues，不依赖仅安全上下文可用的 randomUUID。
- 最近 30 次运行、取消确认与活动任务二十秒轮询；失败保留已有数据并显式显示错误，后台刷新不覆盖草稿或阅读选择。
- 手机序号禁止换行；共用顶部头像在小屏隐藏长昵称、保留可访问名称，修复发现的横向溢出。

## 复现与接入

前端状态测试、浏览器夹具和命令见 [测试说明](../../../webapp/tests/news/README.md)。Gateway 使用 Java 21 执行：

~~~bash
mvn -f service/mytools-gateway/pom.xml test -Dtest=NewsGatewayControllerTest,GatewayRequestFilterTest
~~~

默认开发新闻代理指向 http://127.0.0.1:23200，可用 VITE_NEWS_GATEWAY_URL 更换。生产反向代理须把 `/api/v1/news` 路由至 Gateway，Gateway 再按自己的内部令牌访问 News；内部 Secret 不进入前端。现有 Gateway 新闻功能仍默认关闭，本批没有修改生产配置。

## 限制与后续

- 浏览器测试使用回环地址上的明确夹具登录和新闻。实际认证/owner 隔离由独立 Java 回归验证，本批没有进行浏览器到生产服务的联调。
- 离开或刷新页面后，尚未确认的预览请求不持久化到浏览器；应先查询历史核对结果，再生成新预览。不会把后台未知结果宣称为失败后自动另发新请求。
- 默认开发配置仍出现共用导航 `route.undefined` 国际化警告；新测试说明设置 VITE_ROUTE_HOME=home 可明确首页。Node 26 的 tsx 验证有 module.register 弃用提示。这些是运行环境提示，不能写成所有控制台无告警；定向 Lint 检查已通过。
- 实时来源、真实 MySQL、执行节点/本地来源包、七日采样及生产部署尚未补验；本批未发送邮件、飞书或 QQ。

下一目标推荐为个人邮件闭环：目的地绑定、HTML/纯文本同版内容、发送 Outbox、未知结果对账及模拟回归；之后再进行明确目标的真实渠道验收。
