# 独立新闻分析技能与事件合并

用户要求：重复内容合并；每类约 30 条候选由 DSH 分析，形成最多 20 条事件，其中前 10 条图文详情，最终生成当日报告。

## 实现

- 技能：`service/news-digest-service/skills/analyze-daily-news/SKILL.md`，随个人运行包发布。调用方显式把技能和材料交给 `dsh --profile headless --patch ... -`，工具仍关闭，不依赖全局技能目录或新增账号。
- 采集：个人入口单独构建每类最多 30 条候选并采集正文、原图和已有排序信号，普通 News API 的 20 条协议不变。
- 合并：先以全部候选的紧凑证据做一次跨分类事件分组；同一事件只归入一个分类，再按每类完整材料合并、排序、精选前 20。前 10 是该榜单的详细版本，11–20 为简述。
- 来源：分组只能引用已有编号；代表必须在组内，每条候选必须且只能归入一个组或明确列入榜外。来源链接、图片和原始事件映射由程序关联，模型不能添加地址。不把不同事件仅因同一主体而合并。
- 交付：`index.html` 为当日报告入口，四个分类目录包含图文预览和邮件清单；`daily-report.json`、`event-clusters.json`、分类分析 JSON 保留来源映射、合并理由与排序理由。
- 恢复：技能摘要加入报告上下文；材料、图片、技能或收件人变化时不能复用旧缓存。分析结果未经校验不生成待发送邮件，发送仍沿用现有回执与幂等逻辑。

## 本地验证

- Java 21 编译启用 `-Xlint:all -Werror`，27 项定向测试通过（排序引擎、正文提取、原图提取）。新增检查确认个人候选有 30 条可用证据，普通日报仍为 20 条、10 详情。
- Python 共 19 项测试通过，覆盖跨分类合并、来源及图片归属、30 选 20 的覆盖与排除、少量候选不凑数、图文仅限前十、恢复与技能变化检测、邮件离线校验。
- 技能格式验证通过。
