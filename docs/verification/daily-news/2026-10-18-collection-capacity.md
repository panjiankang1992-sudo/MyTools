# 第十七批：采集数据持久容量额度

状态：本地实现与隔离 MySQL 验证完成。持续目标 ACTIVE，N23 仍为 DOING。

## 行为与边界

- News V8 新建单行容量账本，回填既有文章、GitHub 快照和撤稿用量；旧 V1—V7 SQL 不修改。
- 三类行数上限和正文 UTF-8 字节上限独立约束，默认 250,000 / 250,000 / 100,000 行和 512 MiB。文章每行预留 128 字节到期标记空间，清理可以释放额度，不必申请新空间。
- 采集和清理先锁容量行，再修改具体记录，多个来源、多个仓储实例共用数据库串行门禁；网络请求在事务之外。
- 重复文章、同桶快照、同观测撤稿不重复计费。超限整批回滚，ETag/游标不推进；采集接口给出 `NEWS_028`，来源进入 `STORAGE_FULL` 并冷却 15 分钟。
- 保留清理与额度释放同事务。计数出现负值即失败回滚；管理接口只读报告账本与持久记录是否一致，不自动归零。
- 数据库约束拒绝省略计费字段的旧版插入。仍要求停止旧写入程序再迁移，不能把约束当成任意 SQL 的自动计费机制。
- 发布配置门禁验证额度范围；发布 JAR 门禁要求 V8；默认环境和样例同步。已有日报、投递身份和 UNKNOWN 不被额度清理删除。

## 验证

结果汇总、真实数据库版本、源码哈希与清理证据记录在同目录 `news-collection-capacity-test-summary.json`。

新增测试覆盖：跨来源与跨仓储并发争用最后一个槽位；采集与清理并发；整批技术采集失败后快照/撤稿/正文/游标回滚；外层事务回滚；UTF-8 多字节正文；同内容和同桶重放；降低配置后继续清理；清理到期标记预留；损坏账本失败关闭；管理核对不改数据；旧库回填及旧版无计费写入拒绝；HTTP 安全错误、来源状态和冷却。

真实 MySQL 首轮有一项测试断言失败：数据库正确返回 CHECK 约束错误，但 Spring 将 MySQL HY000/3819 归为 UncategorizedSQLException，原断言只接受 H2 常见的 DataIntegrityViolationException。修正为同时校验底层数据库错误码和约束名，未取消约束或放宽业务写入。最终 11 项全部通过，0 失败、0 跳过。

本批不同测试合计 **244 项通过**：News 本地 195 项、部署 Python 38 项、实际 MySQL 11 项。News 本地报告另有 15 项跳过，其中 11 项已在真实数据库单独执行，最终仍未执行的是 4 项可选外网来源测试。Java 21 编译打包通过，无新增编译告警。8 条监控规则仅完成 YAML 解析；环境无 promtool，未声称 PromQL 或实际加载验收。

发布装配包含 18 个 Java 服务、7 个 Python 服务、153 个任务包及 733 个文件。本批重建 News JAR，其余 Java 使用已有制品；发布包版本、V8 和完整文件清单门禁通过，包内两项 CLI 帮助检查不改变文件清单。最终本地路径和 manifest 摘要见 JSON 汇总，不代表已部署。
