# 第二十一批：消息正文截止与无正文取消

状态：Messaging 协议基础实现、本地验证和隔离 MySQL 验证完成。News 按来源冻结并传播期限尚未实现，整体目标未完成。最新目标工具状态为 BLOCKED，本轮继续了已授权的工程工作；不将局部通过或文档状态视为自动续跑已恢复。

## 实现结果

Messaging V22 新增可选且不可变的 `contentExpiresAt`，现有消息保持空值和原保留策略。新请求的期限需在未来且最多 730 天；发送期限仍最多 48 小时，二者独立。重放不能新增、删除或修改已冻结的正文期限。

执行入口、重试入口以及实际 SMTP/HTTP 调用前检查期限；邮件构造或飞书配额等待跨过期限也会停止，返回 EXPIRED / MESSAGING_028。重试到期正文返回 HTTP 410。已经开始的调用可继续完成，清理保留其实际结果，不承诺撤回外部副本或立即清除在途内存。

新增 `cancel-by-identity`，正文不存在时使用原 owner、目标、幂等键、载荷摘要、严格内容摘要及两个期限进行取消。未创建的消息直接写不可发送的 CANCEL_ONLY 身份；取消与创建并发仍汇合为一个身份。取消额度有限，不能在额度耗尽或结果未知时虚报取消成功。

独立截止定时器每分钟处理一批，不受发送或普通保留开关影响；使用独立持久租约及检查点。正文和计费字节同事务释放，UNKNOWN/SENDING 状态、尝试和身份保留，人工核对与迟到回执继续有效。后台清理可能因故障或积压延迟，发送/重试门禁不等待物理删除。普通保留关闭时管理员仍可执行明确截止清理。

## 剩余与回退边界

本批提供 Messaging 的期限执行基础。News 来源策略、生成时冻结期限、历史读取门禁、片段身份持久化和期限传播仍待实现，不能称为端到端派生内容到期治理。来源原文缓存期限也不能直接推断为派生内容授权期限。

部署时先升级全部 Messaging 写入者，再启用期限客户端。接受过明确期限后必须保留 V22 门禁和截止清理，不能直接回退到只理解 V21 的发送程序。实际节点 IP 定位、真实接收目标与渠道验收、业务备份副本和连续七日观察仍未完成。目标工具的 BLOCKED 原因未返回，现有工具不支持恢复为运行态，因此未声称自动续跑已经恢复。
