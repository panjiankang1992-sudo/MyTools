## 成组操作的根因

实际复测否定了仅写 `Flex Stretch` 就能解决等高的假设：旧自定义按钮吞掉跨轴拉伸，改成单原生 Button 后，自动高度下也出现了 143/176/149px 的不同高度。这个失败结果没有记成验收通过。

最终 `AppEqualActionRow` 不包 Flex：动态迭代直接子节点，等宽测量自然高度，取共同最大值后用精确 min/max 高度再测一次，最后逐个定位。模拟器又揭示多根自定义内容会漏挂载末项，已在共享容器内部用单个稳定key的ForEach虚节点包裹内容闭合挂载流程；调用方业务动作不变。分组修复包验证三动作全部出现，隔离原生探针还验证动态3→2→3及回调。无固定子节点索引、无测量期状态写入、无高度同步循环；分组使用该容器，普通独立按钮继续保持紧凑样式。

组件回归覆盖 406 项测量/定位检查，以及 185 项状态与兼容测量检查；这是代码验证，不能代替最终原生几何复测。
