## 真机发现并修复的问题

原实现向 `ble.startBLEScan` 传入空数组 `[]`，真实系统会拒绝该参数。官方 [API 12 对应时期的原生实现](https://github.com/openharmony/communication_bluetooth/blob/OpenHarmony-5.0.0-Release/frameworks/js/napi/src/ble/napi_bluetooth_ble.cpp#L569) 检查数组长度必须大于零，并单独支持 `null` 表示无过滤。

现已改为 `null`、默认上报延迟及明确匹配模式。新增原生端口回归：mock 会拒绝空数组并验证生产调用使用合法参数。修复后真机扫描成功；策略、20 个传输场景和 12 个页面场景全部通过。
