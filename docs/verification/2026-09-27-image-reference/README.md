# 图片底稿上传修复（2026-09-27）

已移除 App 的 1 MB 拒绝规则，并修复通用 JSON 客户端 2 MB 请求体限制。图片上传端点精确匹配时允许 7 MB JSON（容纳 5 MB 图像 Base64），其他端点仍保持原上限。

原图允许 64 MB、2 亿像素以内 PNG/JPEG。5 MB 且 1600 万像素以内保持原字节；超出时以长边 2048 起等比例缩放、无损 PNG 编码，必要时逐级缩小直至满足后端 5 MB/1600 万像素要求。不裁切、不放大、不修改原文件，PNG 保留透明区域。UI 显示自动适配提示。这里没有将后端上限改成无限，也不需要更换已发布的执行器任务包。

## 验证

- 18 项输入大小/比例/维度策略断言通过。
- 通用认证 API 回归及图片端点 Base64 载荷边界通过；其他路径不能借此绕过 2 MB 限制。
- 在模拟器原生 ImageKit 执行正式处理代码：1,923,432 字节原样通过；12,600,274 字节适配为 4,661,336 字节；8000×6000 JPEG 适配为 2048×1536 PNG。见 native-results.json。
- 正式 assembleHap 成功、无警告；修复包已覆盖安装到模拟器及已连接真机，保留账号数据。
- 原生验收包只装在模拟器，已恢复正式入口；本轮本机测试监听和端口转发已清理。
- 本轮没有在真机选择用户私人图片做上传；原生编解码用模拟器、真机仅验证安装成功。

HAP 摘要与构建信息见 build.json。正式后端三次上传均返回 HTTP 200，SHA-256 与模拟器产物逐一一致，见 live-upload.json。
