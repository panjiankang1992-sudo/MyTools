# 登录续期可靠性修复

## 现象与证据

用户报告未满三十天就反复需要登录。2026-11-04 现场确认：

- 运行中的 Identity 服务仍显式配置 `--identity.refresh-seconds=2592000`，访问令牌仍为十五分钟。
- 最近手机会话在数据库中仍有效，截止日期在十二月，未被撤销；不是三十天配置回退。
- 手机当时位于登录页。旧版本日志不足以还原每一次退登请求，因此不把单条历史请求的超时原因写成已证实事实。
- 客户端和服务端存在可复现的缺口：服务端消费旧刷新令牌后立即轮换；响应丢失或客户端保存新令牌失败时，下次只能使用旧令牌，遭到明确拒绝后客户端清除登录状态。此前网络路由支持在活动局域网或 IPv6 线路上续期，弱网会增加触发机会。

## 修复协议

1. App 使用系统随机 UUID 生成 `rotationId`，与旧令牌一起保存在系统安全存储中，确认保存成功后才发送刷新请求。
2. 断网、响应解析失败、保存新令牌失败或进程退出后，App 继续使用已保存的同一次操作标识。首次意图保存失败时禁止发送轮换请求。
3. Gateway 透传经过格式校验的可选 `rotationId`；未升级的客户端保持原有协议。
4. Identity 在数据库事务中锁定会话，同时更新令牌摘要、三十天期限和最近一次操作回执。每个会话最多保存一条回执。
5. 新刷新令牌由服务端 HMAC-SHA256 密钥、专用域、会话 ID、旧令牌与操作 ID 确定性生成；数据库仅记录旧令牌和操作 ID 的 SHA-256 摘要及版本，不保存明文刷新令牌。
6. 同一个旧令牌与同一个操作 ID 只能恢复最近一次成功结果，不再次轮换，也不延长原期限。下一次轮换淘汰此前回执。
7. 旧令牌缺少原操作 ID、操作 ID 不同、版本落后、会话过期、主动退出、账户停用或凭据版本变更均被拒绝。服务重启不会丢失回执。
8. 完成新令牌的安全保存后移除本地操作 ID。界面只记录固定诊断状态，不输出令牌、操作 ID、账号或响应正文。

恢复重试仍需原操作材料，不将旧刷新令牌开放为长期可重复使用的凭证。令牌轮换与撤销的设计参考 [RFC 9700 第 4.14 节](https://www.rfc-editor.org/rfc/rfc9700.html#section-4.14)；这里的持久化操作恢复属于本项目实现。

## 验证

- Identity：23 项测试通过，包含新增 10 项响应恢复、服务对象重建、并发、期限、撤销和凭据边界测试。
- Gateway：200 项测试通过，验证新字段转发和原接口兼容。
- App：38 项实际 ETS 网络行为测试通过，新增响应丢失后冷启动恢复、保存失败恢复、意图未保存禁止发请求、并发合并和明确拒绝清理测试。
- App：42 项三级端点协商测试、认证响应规范化和认证操作版本检查通过。
- 旧源码运行新增回归场景时，缺少持久化操作标识的断言失败；修复后通过。
- 更新了一条已过时的登录 UI 静态检查，使其识别现有 `AppTextAction.description` 属性。
- ArkTS 构建通过。仍存在原先 `DownloadToolsPage.ets` 的剪贴板权限提示，本次没有新增编译告警。
- 已覆盖安装到连接的真机，应用数据保留。用户重新登录后，连续两次强制结束进程再启动，确认进程确实退出并更换 PID，均恢复相同账户。第一次账户页面也确认存在退出登录操作，没有回到登录页。脱敏证据见 `native-cold-start.json`。
- 本次真机检查覆盖关闭重开后的本地凭证恢复；没有在真机上等待三十个自然日。三十天期限、过期与自动续期边界由服务端实测和前述自动化测试覆盖。

线上使用既有独立测试账户验证：新会话三十天、访问令牌十五分钟；首次续期后重启身份服务，使用原操作成功恢复相同刷新令牌；缺失或不同操作标识被拒绝；六个并发重试得到同一轮换结果；后续轮换淘汰前一回执；注销阻止恢复。测试会话已注销，没有修改用户会话或密码。

## 发布与回退

- 发布目录：`/opt/yuyutian/mytools/releases/auth-refresh-recovery-20261104-v1`。
- 只修改运行中 Identity JAR 的六个成员和 Gateway JAR 的两个成员，其余成员逐项比对相同。
- 发布前将五个相关生产类的字节码与此次修改前源码的编译结果比较，全部一致。
- Identity 新增 Flyway V3 回执表；既有会话表和用户记录不做数据改写。
- 保留原有启动参数及旧 JAR，发布脚本持有共享发布锁并验证当前基线。失败自动撤销本次两个覆盖配置。
- 手动回退前确认当前运行版本仍是本次版本，再移除 `deployment.json` 所列的两个 `dropIn`，执行 `systemctl daemon-reload` 并重启对应服务。不要删除回执表或修改已应用的 Flyway 记录。

旧版已清除的本地令牌无法由此次修复补回。这部分用户需要再登录一次；新版本从此建立可恢复的续期操作。
