# 历史视频封面修复验收

范围：当前账户全部 1,471 条活动视频，包括按小于 100 MiB 规则归入图片页的视频。

## 修复

- 保留公共 `.thumbnails` 路径，兼容误加用户名层的旧记录。
- 复用旧视频包 `thumbnail.jpg`，对缺少旧主键关联的条目，先校验所有者，再按 SHA-256 与长度匹配旧封面。
- 禁止把视频原文件作为图片预览返回。
- 将媒体标签查询移出 JDBC 行映射，避免并发请求嵌套占用连接造成连接池耗尽。
- 新建仅含源文件准备、探测、抽帧、登记和完成步骤的封面任务，并发上限 2；下载后封面同样使用此任务。

## 执行与验证

- 修复路径和内容关联后，1,399 条直接复用可读封面。
- 对余下 72 条提交任务：69 条成功，3 条因资产存储位置仍引用迁移前路径而失败。
- 最后 3 条在本地资源目录找到原文件；完整 SHA-256 与长度校验、抽帧诊断及旧截图查找结果见 `legacy-preview-recovery.json` 与 `legacy-preview-alternatives.json`。原视频保持不变。
- 未更改原视频、既有标签或 100 MiB 分类规则。
- Java 媒体服务 28 项测试通过；封面任务迁移回归测试 1 项通过。
- 首次 V170 遗漏非空 child_aggregation_policy_json 导致调度器启动失败；确认无部分业务写入后，通过 Flyway repair 清理失败记录并应用修正迁移，服务已恢复。成功应用后的迁移未再修改。

最终 HTTP 验收见 `http-verification.json`；任务审计保留首次 3 条失败，单独记录本地校验抽帧的诊断结果，不把失败任务改成成功。

部署：媒体服务 historical-preview-20260927-v3；调度器 historical-preview-20260927-v4。
