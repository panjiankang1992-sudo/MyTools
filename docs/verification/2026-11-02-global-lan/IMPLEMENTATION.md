# 全局局域网连接改造

2026-11-02。后端已部署；最终客户端签名包已构建。用户报告真机暂时无法连接，最终包安装和真实账户切网验收待完成。

## 修复原因

旧 EndpointRouter 在迁移期直接返回公网，局域网发现实际关闭。共享客户端、认证刷新、长轮询、播放器及部分自有图片仍各自保留地址；仅切换页面状态不能全局切换连接。

## 最终行为

- 会话只有一个活动业务地址。JSON、二进制上传、流下载、令牌刷新、注销、旧 API 实例和长轮询逐次读取它。账户与本地缓存归属仍绑定规范化公网身份，避免切网生成第二份书架。
- 首次通过 HTTPS 获取短期材料，再对名单内私网入口执行匿名 HMAC 挑战和固定地址的身份探针。新入口固定 23201，mDNS 类型为 `_mytools-gateway._tcp.local`，不接受旧单体 23110 或额外 mDNS 地址作为活动端点。
- 有效材料可在内存复用；已验证 LAN 可续签。后端重启拒绝旧 probe 时最多续签一次并重试，避免十分钟无法恢复。
- 原生播放、视频和有声书随地址切换保留位置与暂停意图。预取票据清理，试听停止后由用户重试。DSH 换取独立 LAN 网页会话，公网 Secure Cookie 保持原策略。
- 自有头像和书架封面跟随会话地址；普通书源、OPDS、第三方图片继续执行原私网保护，不能借封面分支发送 MyTools 凭据。
- LAN 失败先更新全局后续请求路由。仅原生网络失败的只读请求可补发公网一次；响应校验失败和写请求不自动重放，取消和本地磁盘失败不错误触发降级。

## 后端部署

双物理网卡由专用 Nginx 23201 入口接入。迁移完成的接口进入同一 Gateway；明确列出的历史电子书、本地文件、云文件、阅读数据管理、单数书源发现和反馈保持原服务。只有冲突的只读媒体票据在 Gateway 返回 404 后访问旧服务，其余路径没有隐式兜底。

Gateway 使用现部署 JAR 的六个类增量，逐项验证其余 391 个成员保持一致。新 systemd drop-in 保留原启动参数，并检查实际生效 JAR。服务健康，Nginx 配置校验及热重载通过，Avahi 广播启用。旧服务及既有公网站点保留。部署回滚入口见 `deployment.json` 与 `runtime-verification.json`。

## 验证与交付

- `tests.json`：真实 ETS 路由、传输、业务 API、播放器、封面及安全边界回归；Gateway 197 个测试与部署工具 18 个测试通过。
- `server-verification.json`：两个接口地址共 20 项 HTTP 认证/内部路径拦截检查通过，无效 probe 被拒绝。真实账户请求和跨网切换未冒充已验证。
- `app-build.json`：最终 HAP 的源代码摘要、签名验证、大小及 SHA256。构建期间源文件一致；此后工作区出现并行 DSH 能力修改，签名包保留已验证的构建快照，这些后续修改未纳入本包。现有下载页剪贴板权限提示仍为既有警告，没有新编译警告。
- `initial-app-build.json` 与 `device-install.json`：较早的核心路由包已经签名验证并安装；系统锁屏阻止冷启动验证。随后头像/封面补齐的最终包尚未安装，不能将早期安装记录当成最终验收。
- `lan-reachability.json`：本机当前不能直达服务器私网；设备不可用，因此外部设备的实际 LAN 可达性及完整切换仍待验证。
