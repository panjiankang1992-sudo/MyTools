## 验收中修复

1. 线上 Comfy 路径检查拒绝输入目录之外的绝对路径。新适配器通过受限本机 `/upload/image` 上传底稿，严格校验返回的文件名和子目录，给 LoadImage 绑定相对输入路径。
2. 视觉模型对插画可能把 JSON 放入 thinking 字段，普通输出在思考耗尽预算后没有最终内容。1.1.2 使用 `format=json`、`think=false` 和有界输出预算，严格解析唯一 prompt 字段；不将普通思考内容作为结果。照片与同一张失败插画重新实测分别约 8.5 秒和 4.9 秒完成。新增测试覆盖两个响应字段、非 JSON、截断响应与附加字段拒绝。首次暂存的 1.1.0 未用于正式调度，1.1.1 的失败任务保留用于审计。
3. 长任务用 systemd 独立验收进程运行，SSH 断线不会影响任务与记录持久化。

## 验证与运行边界

1.1.2 执行包 16 项本地测试通过；此前图片服务 18 项、Scheduler 3 项测试及 App 构建通过。真实验收已验证两个新模式及文生图往返链路；本次不声称覆盖长期满负载、所有输入类型或多张图生图质量。候选源文件保留 `validated=false`，线上启用依据本次固定摘要与实测记录。

Comfy 图生图采用固定候选 denoise=0.65，目标尺寸不同比例时居中裁剪。上传到 Comfy 的底稿保存在其受管输入子目录，用于任务恢复；当前不自动清理历史底稿。

回退使用部署脚本 `rollback`，在无执行中任务时恢复旧图片服务入口，保留 V153/V154、历史任务、新包与生成数据，使已有快照仍可执行。执行器新包和调度数据库不做破坏性降级。
