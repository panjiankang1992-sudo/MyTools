# 公司网络下 DSH 连接排查

2026-11-14 下午，用户报告连接公司网络后 DSH 再次无法使用。本轮没有发布新的业务、代理路由或 App 变更。

## 已确认

- 已通过当前 SSH 配置验证 Ubuntu 连通；DSH、Nginx、Gateway 均运行正常，DSH 没有重启。
- 真实上游 `/api/remote.mux` 握手返回 101；公网与 IPv6 代理的匿名实时请求返回 401，未复现早上的错误分流 404。
- 已连接手机显示 MyTools 当前线路为“公网”，DSH 最初停在“暂时无法打开 DSH，请检查网络或稍后重试。”错误页。
- 手机重试曾显示已有会话内容，但模型尚未加载，不能将此视为完整连接恢复。重新进入后再次显示错误页。
- 手机 ArkWeb 日志在 14:39–14:40 多次记录 DSH 公网入口的 `NetworkTransactionTimeout`，部分请求 `receivedBodyBytes: 0`。导航切换时取消的相关请求持续约 56–84 秒，类型为资源请求；这些取消事件不能冒充主框架自身超时的错误码。
- 14:39 起的临时服务端诊断记录到公网入口 9 次资源/其他请求 401、1 次 500；观测窗口没有收到新的换票或主页请求。不能据此单独认定 Cookie 失效就是根因。
- 当前电脑能访问公网入口，匿名主页返回 401，公开 CSS 返回 200，但分别耗时约 5.2 秒和 15.6 秒。该电脑的结果不等同手机公司网络的连通性。

## 结论边界

已确认手机公网网页链路存在请求长时间收不到响应的问题；公司网络限制、运营商/Cloudflare 链路波动，以及旧网页认证状态的影响仍需区分。尚不能宣称公司网络屏蔽了 DSH，也不能宣称本轮已修复。

已请求用户在方便时改用移动数据重新进入 DSH，以完成同一设备对照。尚未记录到此对照结果。
