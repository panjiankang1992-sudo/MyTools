用户明确同意后，通过配置的 SSH 通道读取启动口令，仅在内存中提交 APP，未输出或保存口令。登录成功；覆盖安装并重启 APP 后 Cookie 仍有效，历史会话可加载。

继续验证时复现首次声明弹窗点击穿透：点击“继续”会触发后台菜单。移除 APP 原有按坐标猜测侧栏按钮、全局 Escape 和原生透明遮罩的逻辑；增加 ArkWeb 对话框显式 pointer-events 与 inert 背景触摸隔离。新版中“继续”正常关闭弹窗；工作区菜单、会话侧栏、新建会话和发送按钮可点击。

实际发送不调用工具、不修改文件的测试消息，模型回复 `DSH_OK_20260928`，见 dsh-reply.png。测试会话 `MyTools acceptance reply check` 已通过 DSH 归档功能移出正常列表；当前菜单无永久删除入口，故服务端仍保留归档记录。本轮验证了聊天往返，未逐项执行 DSH 的终端、文件写入、定时任务等工具能力。

## 二维码

APP 内置二维码编解码引擎，以 N-API 后台任务生成 RGBA 图片、识别选定图片。使用固定提交的 [QR Code generator](https://github.com/nayuki/QR-Code-generator) 与 [quirc](https://github.com/dlbeer/quirc)，来源和 SHA-256 见 cpp/vendor/qr/SOURCES.json；许可证随 APP 打包且可查看。无服务端请求。

支持文字与链接生成、PNG 保存、图库图片识别、文件图片识别、系统相机扫码及复制识别内容。生成成功直接展示结果，避免结果藏在长页底部；取消扫码不再报失败。生成显式使用 UTF-8 ECI，输入限制 2950 UTF-8 字节，识别图片按比例缩至最长边 2048；修复默认连通区域上限导致密集长内容二维码无法识别的问题。

验证结果：

- C++ 实际编解码往返：链接、中文换行、2900 / 2950 字节内容、镜像；空图无结果、错误尺寸与过长输入拒绝。
- 模拟器：输入文字生成二维码，保存 Download/MyTools-QR.png，再从系统文件选择器读取，解码内容完全一致。
- 系统相机扫码界面正常打开，取消后按钮恢复、无失败提示；本轮无真机光学扫码结果验证。
- 构建签名成功，无 WARN / ERROR。已安装模拟器，真机未连接。

测试文件清理：用户明确同意后完成系统文件管理首次声明，永久删除本轮生成的 Download/MyTools-QR.png（取消“移动到最近删除”），复查 Download 从 3 项变为 2 项且测试图不再存在。未修改其他文件。
