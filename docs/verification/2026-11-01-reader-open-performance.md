# 阅读打开链路优化

## 目标与范围

目标是优先显示当前阅读位置，减少打开链路中的串行等待与重复工作，保持缓存隔离、取消和续读语义，并提供明确的加载反馈。本轮修改鸿蒙客户端，不修改后端或部署服务器。

## 已确认的问题与处理

| 问题 | 处理 | 验证 |
| --- | --- | --- |
| 远程列表点击后先等待封面下载与云端进度，详情迟迟不显示 | 详情立即使用列表元数据与已有封面，缺失封面、进度后台补齐；切书和返回使旧结果失效 | 封面和进度请求均挂起时详情已显示；缓存封面零下载；快速连续点选保留最后选择 |
| 首屏挂载前一章、当前章和后续二十章，大 TXT 会同步读取窗口中的磁盘分块 | 初始只挂载当前章和下一章，边界每次增加一章；书源二十章预取独立延后执行 | 千章目录恢复到中间章节时，初始分块读取由 22 次变为 2 次；向前、向后扩展和末章边界通过 |
| 远程缓存未命中时先请求进度，再取票下载 | 进度恢复与下载并行，已有本地记录不重复查询 | 模拟进度在下载开始后才返回，打开仍完成；缓存命中六种文件格式均无进度或取票请求 |
| TXT 解析缓存只接受两兆字符，并在每次命中时重新 JSON.parse；第一次远程下载也不填充该缓存 | 独立章节对象共享不可变字符串，单本最多八兆字符，合计十二兆字符、最多四本，按使用顺序淘汰；首次下载绑定持久副本 | 账号/文件版本隔离、对象修改隔离、容量限制、淘汰和首次下载复用测试通过 |
| 大 TXT 恢复时先读取空正文，再加载磁盘索引章节 | 加载当前窗口后再取得正文、恢复章节内位置 | 恢复第 800 章及章节内 40% 位置的用例通过 |
| 书源正文显示前等待缓存写入；每写一章都对整本缓存做文件时间排序 | 正文先显示，写盘失败不阻挡阅读；未达到一万章淘汰门槛时不排序 | 模拟磁盘写入失败，正文仍可读 |
| 加载阶段反馈不足，某些成功路径仍保留加载提示 | 显示书名、加载指示、下载 MB 和正文准备阶段；支持取消；解析成功统一清除遮罩 | 实际打开方法与状态切换测试通过；初始章节失败显示重试入口 |

云端进度与下载并行，但首次没有本地检查点时仍等待进度接口完成，以避免用默认开头覆盖正确续读位置。接口原有超时及取消机制保留。打开日志仅输出来源类型、文件格式、成功状态与内容准备耗时，不包含书名、路径、账号或凭证。

## 验证

- `bash app/scripts/test-reader-open-performance.sh`：五组行为测试及合成缓存微基准。
- 阅读取消、打开版本隔离、账号隔离、跨章节、分页、视口、定位、进度同步和书源缓存策略检查通过。
- 目录、书架、反馈交互与远程下载、传输完整性、文本负载检查通过。
- 修正两条已有静态断言：页脚高度已是 44vp；隐私页删除操作已使用 `AppDangerPillButton`。相关产品代码未因断言而改动。
- `assembleHap` 构建生成签名安装包。既有下载页 `READ_PASTEBOARD` 权限编译警告与本轮修改无关。

合成微基准使用约 413 万字符、1000 章的文档，连续读取 20 次：旧 JSON 反序列化约 28.32ms，独立章节对象复制约 0.23ms。这仅比较 Node 环境下的缓存读取步骤，不代表真机打开耗时；旧实现还会因该样本超过两兆字符而跳过缓存。

## 边界

本轮 `hdc list targets` 无连接设备，未测量真机首帧、网络吞吐、峰值内存或视觉效果。首次远程打开仍需下载文件；EPUB、MOBI 和大型 TXT 的完整解析/索引仍有成本。TXT 解析快照为会话内缓存，应用进程退出后不保留；文件缓存仍按既有策略持久保存。不能据此承诺所有格式秒开。
