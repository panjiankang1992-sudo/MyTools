# LTX 正式接入与独立素材验收

日期：2026-09-21。结论：任务执行链路和 GPU 混合排队通过，动作遵循未通过，产品入口保持关闭。

## 已交付

- 发布 `video-ltx-20260921-v2`，不可变包 `video_generate/1.1.1`，迁移 V163/V164。服务同时列出 VACE 与 LTX；App 优先选择已准入模式的模型。
- LTX 接收图片与中文提示词，在共享 GPU 锁内完成本机视觉模型描述/翻译、卸载、视频生成。固定模型和工作流，原生比例生成后补齐 640×640，49 帧、16 fps、静音。
- 持久保存实际英文提示词、提示词修订、原生尺寸和输出摘要。任务依赖补齐 Pillow 12.1.0。
- 保留 QQ 下载与标签修复。v1 Scheduler 与原发布相比仅增加 V163；v2 新增 V164，重组 JAR 每个成员摘要与本地构建一致。执行器 JAR 保持原版，包索引保留所有已钉版本。
- 修复真实部署发现的 systemd 片段顺序、执行器能力键、辅助脚本业务鉴权/202 状态码以及 Ollama 完整 JSON 位于 `thinking` 的兼容问题；非法响应仍拒绝生成。

## 实测结果

| 项目 | 结果与边界 |
|---|---|
| 连续任务 | 10/10 成功，每条 18.06–18.08 秒，包含本机中文提示词整理、调度与文件编码；不是单独模型时间，也不是完整 App 端到端时间 |
| 规格 | 每条实际解码 49 帧，640×640，16 fps，约 3.063 秒 |
| GPU | Worker 采样峰值 11554 MiB，不能当作硬件精确峰值；返回时最低可用内存 15167 MiB |
| 独立样例 | 三类新素材 × 两种子，共 6 条；随后 4 条重复样例补足连续十任务，不冒充新增独立样例 |
| 画质/动作 | AI 检查全部 490 帧联系图；正式组 2/6 有限通过，低于至少 5/6 的门槛 |
| 混合 GPU | 受控持锁 130 秒，26 次观察中图片/标签均排队；最后观察到 125.46 秒仍排队。释放后视频、图片、标签全部成功 |
| 本地检查 | 新包 56 项测试、Java 35 项测试、辅助脚本 3 项回归通过；Scheduler 打包、App assembleHap、差异空白检查通过 |

混合负载是**受控等待加真实推理**，不是八分钟模型推理测试。视频和独立标签步骤通过正式 Scheduler 提交，图片通过图片服务真实创建。独立标签定义 `video_ltx_tag_acceptance` 为无定时触发的手动验收定义，不进行虚构资产回写。

## 未准入原因

- 商品两条：主体、红色和连续运镜基本保持，有限通过；精确相机轨迹仍有限。
- 人像 seed42：后段低头并持续闭眼，未完成自然眨眼恢复，偏离头部稳定要求。
- 人像 seed932：微笑可见，但未见完整眨眼，核心动作未完成。
- 风景 seed42：水面几乎保持镜面静止，要求的水波没有可靠呈现；相邻帧平均绝对差仅 0.201，仅作辅助证据。
- 风景 seed932：整体构图发生位移，未可靠满足固定镜头和局部水波要求。

没有将颜色稳定、文件可播放或任务成功当成指令遵循。评分为 `ai:codex` / `notHumanReview=true`，方法是全部解码帧联系图，不声称完成真人连续播放验收。详细评分见 [reviews.json](reviews.json)。

## 当前边界与下一步

- 两个模型的所有产品模式继续关闭。未以这批任务证明 VideoService 资产登记、Range、真机播放链路通过；本轮没有安装新 HAP 到真机。
- 中文提示词转换已保留原动作语义，问题主要在生成模型对动作/固定镜头的执行，不能用删除用户动作要求或挑种子来提升通过率。
- 后续先做开发集动作对照实验：固定翻译后提示词、相机静止与局部动作分开、比较允许范围内的 conditioning 参数；改动使用新工作流修订和新不可变包。当前独立组若用于调参即转为开发集，重新采集保留组后才能再判准入。
- 多图、文生、视频改编等模式仍需逐模式验收，不能继承首帧测试结论。
