## 真机实测

1. 手机蜂窝网络下，443 的 TCP 握手未完成；8443 的浏览器 HTTPS 请求返回正确的 401 鉴权响应。ICMPv6 可达，手机 DNS 地址与主机当前地址相符。该证据不能确定是哪一段设备实施了端口限制。
2. App 匿名 HMAC 挑战通过，认证用户接口成功，实际选中 IPv6，界面出现 IPv6 标识。源站元数据记录对应 POST/GET 200。
3. 存储的可信描述支持后续冷启动直接通过 IPv6 请求 bootstrap，元数据记录 GET 200；失败时能够回公网取得材料。
4. 大书源同步在当前蜂窝链路上约 20 秒超时，App 自动切回公网。修正恢复调度后，30 秒冷却结束再次探测，成功回到 IPv6；日志有完整的 IPv6 → PUBLIC → IPv6 顺序。
5. DSH 通过 IPv6 完成票据换取和页面资源访问；页面资源有 200 响应，但此次加载超过 60 秒。已补上首次 IPv6 页面超时/网络错误的独立公网回退，并通过真实 Index 方法的自动测试验证仅执行一次、不会重放已挂载页面操作。最终版本的这一降级分支仍需对应网络条件下继续观察；不将资源返回 200 等同于所有交互验收通过。
6. 当前可连接的 Wi-Fi 不在家庭服务所在局域网，无法现场验收真正的家庭 LAN → IPv6 切换。LAN 行为和故障转移由自动测试验证，家庭 Wi-Fi 实测仍待完成。

## 性能结果与限制

轻量认证 API 的源站处理时间约 10 ms；这个数值不包含完整手机端网络耗时，不能当作端到端延迟。

当前蜂窝链路 TCP 样本显示 RTT 约 45–50 ms、拥塞窗口 2–5 个段，并出现明显重传。书源同步在约 20 秒内只完成约 1.2 MB 的响应传输，触发 App 原有的请求时限。gzip 已生效，示例元数据包含 `gzip application/json`；它降低 JSON 体积，但不能解决链路丢包。

因此本次确认的是自动选路、直连可达、安全校验、故障降级及恢复机制。**尚不能证明 IPv6 在当前蜂窝网络的大文件吞吐一定优于 Cloudflare，也没有测得可承诺的提速倍数。** 没有修改全机 TCP 拥塞算法、其他服务带宽策略或路由器全局防火墙。

首次登录、过期会话冷启动刷新仍使用可信公网入口。备用 IPv6 健康结论超过 60 秒时，LAN 故障会先回公网，再重新发现，避免发送凭据到未经当前网络验证的候选。普通浏览器和不可修改的第三方 App 不会自动执行本次策略。
