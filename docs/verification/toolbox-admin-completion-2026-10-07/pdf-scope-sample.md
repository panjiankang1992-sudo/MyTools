### 决定性复核（父会话亲自做，`scripts/pdf-determinism-check.mjs`）

**问**：那 61,586 vs 61,066 的差异，会不会来自时间戳之类的非内容因素 ✗？

**答**（实测）：

```
同输入两次渲染: 逐字节相同（确定性 ✓）
原始  vs 编辑后: 不同 ✓ eda44edf9a060f78 vs 794e737535d8930a
```

**渲染是确定性的** ✓ —— 同一输入两次产出**逐字节相同** ✓。
因此**任何字节差异只能来自输入内容** ✓✓ —— 那 520 字节的差异**就是那次编辑造成的** ✓。

**这比文本提取更强** ✓：它排除了"差异来自别处"这一整类可能 ✓。
可重跑：`cd toolbox-web && npx tsx scripts/pdf-determinism-check.mjs`。

## ⚠️ 第 163 轮更正：我上面的「渲染确定性」论证**不成立**

我在第 160 轮用 `scripts/pdf-determinism-check.mjs` 得到「同输入两次渲染：逐字节相同」，
据此论证"字节差异只能来自内容" ✓。**这个论证是错的** ✗：

- 那次"相同"只是**同一进程内**成立 ✓（字体子集名生成一次后被复用）；
- **跨进程就变了** ✗ —— 我复跑同一脚本，哈希从 `eda44edf9a060f78` 变成 `985e2f5e5110b7e1` ✓，
  而输入完全没变 ✓；
- 原因：**pdf-lib 的子集字体名带随机后缀**（如 `NotoSansCJKsc-Regular-7098480789`）✗。

**所以"同内容两次生成字节也不同"，字节 sha256 不能当"内容变了"的判据** ✗ ✓。
反向验证里就出现过**"字节不同但文字层相同"的假信号** ✓ —— 若我沿用字节判据，会得出错误结论 ✗。

**正确判据是 PDF 的「文字层」** ✓（子代理用站点自带 `pdfjs-dist` 读取，**不新增依赖** ✓）：

```
改动后预览：文字层片段 = "…1. kuài zhuǎn4bfa 2. shuǐ学生练习 | 第 1 / 1 页"   ← 独特值在 ✓
改回后预览：文字层片段 = "…1. shān 2. shuǐ学生练习 | 第 1 / 1 页"              ← 独特值消失 ✓
```

**这比我那套字节论证更直接** ✓（它直接看到内容 ✓，而不是靠"排除其它因素"推断 ✓）。
