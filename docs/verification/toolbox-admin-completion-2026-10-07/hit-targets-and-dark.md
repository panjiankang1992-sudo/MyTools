# 命中区实测（44px）与深色主题尝试（目标第 3 项，2026-10-07）

## 一、命中区实测：**移动端 44px 要求未满足** ✗

用 `getBoundingClientRect()` 实测 **3 个管理页 × 2 个视口（375 / 1280）= 209 个可点击元素**（只读尺寸，**不点击**）。

| 视口 | 测量结果 |
| --- | --- |
| 375×812（移动）| 按钮普遍 **高 40px** ✗（如「新增教材」84×40、「恢复导入包」98×40、「查询」150×40、「编辑」28×40）|
| 1280×900（桌面）| 控件 **高 34px**（Naive UI 默认；桌面不受 44px 规则约束）|

**合计 209 个元素中 174 个 < 44px** ✗。

### 怎么读这个结果（避免误报）

设计第 176 行把 44px 与 **16px 字号、键盘可达**并列写在"移动端／无障碍"一节，
第 49–55 行的"手机 44px"也是**手机**语境。
所以：
- **桌面 34px 不算违规** ✓（Naive UI 默认尺寸，桌面校招）
- **移动端 40px 是违规** ✗ —— 375 宽下按钮应当 ≥44px 高 ✓

**结论**：**移动端命中区不达标** ✗。这一条是**实测出来的**，不是目测 ✓。

证据：`evidence/hit-targets.json`（逐元素 `page/viewport/tag/text/w/h` + `belowMin` 清单）。

## 二、深色主题：**两次尝试都没能证明，如实记为未达成** ✗

### 尝试 1（第 125 轮）：`prefers-color-scheme`

用 `Emulation.setEmulatedMedia({features:[{name:'prefers-color-scheme',value:'dark'}]})`
拍了 3 张并命名 `dark-*`，**随后发现它们是浅色** ✗ ——
该应用用**自带的深色开关**（`App.vue` 的 `dark` ref），**不跟随系统偏好** ✓。
**已删除那 3 个文件** ✗（留着会让人以为深色已覆盖）。

### 尝试 2（第 127 轮）：合成点击

实测发现存在 `button "切换深色模式" 34x34` ✓（说明开关是真实按钮）。
于是用**合成 `el.click()`**（绕开未定位的"真实鼠标点击不稳定"）点它，并用
`getComputedStyle(document.body).backgroundColor` 前后对比：

```
list:   clicked       bg rgba(0, 0, 0, 0) -> rgba(0, 0, 0, 0)  变化=false
new:    not-found     bg rgba(0, 0, 0, 0) -> rgba(0, 0, 0, 0)  变化=false
editor: not-found     bg rgba(0, 0, 0, 0) -> rgba(0, 0, 0, 0)  变化=false
```

**两个问题，都属于我的测试，不属于产品** ✗：
1. **探针选错了**：`body` 背景是 `rgba(0,0,0,0)`（透明）✗，**它本来就读不出主题变化** ✗
   —— **这是我的错误**，正确探针应当是根元素的主题类名或 Naive UI 的 provider 配置 ✗；
2. `new` / `editor` 两个页面报 `not-found` ✗ —— 说明这两页上我没找到那个按钮 ✗
   （可能是 aria-label/文本不同，或它只在某些布局下渲染 ✗）。

**所以这一项既不"通过"也不"未通过"，而是"我还没能把它测出来"** ✗ ✓。
那 3 张 `dark-*` 截图**也已删除**（它们未必真是深色）✗。

## 四、修复尝试（第 128 轮）：**部分改善，未达标**

设计第 176 行要求 44px，所以上表那 174 个是**真缺陷**。本轮做了两轮尺寸改动：

| 轮次 | 改动 | 总低于 44px | 375 宽下 |
| --- | --- | --- | --- |
| 修复前 | —— | **174** | 48 |
| 第 1 轮 | 三个管理页的 `@media (max-width: 720px)` 内加 `min-height: 44px` | **138** | — |
| 第 2 轮 | 改为 `:deep(...)`（**作用域样式选不中 Naive UI 子组件**）+ 给按钮加 `min-width: 44px` | **119** | **29** |

**改善是真实的** ✓（174 → 119，降 32%；移动端 48 → 29 ✓），

**但仍未达标** ✗ —— 剩下 29 个里主要是 **Naive UI `NInput` 内部的原生 `<input>`（28–34px 高）** ✗：
外层我加了 `:deep(.n-input)`，但 Naive UI 用 `--n-height` 之类的变量控制内部输入框高度 ✗，
单纯 `min-height` 选不中它 ✗。

### 我为什么停在这里

- 继续要改的是**组件库内部尺寸变量**（`--n-height`），影响面比"移动端补一层 min-height"大得多 ✗；

### 还漏掉的一处

测量里那个 **`切换深色模式` 34×34 的按钮在 `App.vue` 的顶栏** ✗，
**不在**我改的三个管理页里 ✗ —— 所以**它没有被我这次改动覆盖** ✗ ✓。
