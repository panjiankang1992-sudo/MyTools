## 本轮修复

换票失败原先一律显示账号认证提示。现将 `BusinessTransportError`、`BusinessResponseError` 识别为连接或响应问题，保留重试入口，避免让用户因网络失败反复登录。认证失败仍使用原有账号提示；不改变鉴权、账号状态或重试策略。

修改 `Index.ets` 的错误分类，并在实际方法测试中覆盖网络失败、响应失败和认证失败，验证连接锁、加载状态和计时器均释放。

## 网络诊断边界

源站日志记录合并插件脚本压缩后约 3,974,678 字节。直连 ArkWeb 中，该请求在截止时仍未完成；基础资源下载也存在明显延迟。界面树显示的 Web `about:blank` 不代表真实页面地址，调试器确认主文档已进入正确 HTTPS 域名，因此不能把此前现象直接判定为换票失败。

为分离页面问题与网络问题，临时副本启用官方 ArkWeb 调试和代理接口，通过已配置的 SSH 通道提供仅允许 MyTools、DSH 两个域名的 HTTPS CONNECT 转发。TLS 证书校验及 MyTools/DSH 鉴权保持正常，没有解密请求、读取 Cookie 或存储请求头/响应正文。该条件下网络请求采用 HTTP/2，页面和接口成功返回。

对照同时改变了网络出口和传输协议，不能据此断言 HTTP/3 是唯一根因。正常包最后一轮直连成功也不能证明无缓存首次加载的公网稳定性已解决。本轮没有修改 Cloudflare、Nginx 或生产服务。
