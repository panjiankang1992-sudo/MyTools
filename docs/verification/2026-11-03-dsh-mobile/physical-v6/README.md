# DSH v6 真机安装与验证

2026-11-03，在 USB 真机 BRA-AL00 上安装 v6，保留既有应用数据和登录状态。安装、启动与修复回归通过；公网完整功能验收未通过。当前手机停在 DSH 超时重连页面。

## 本轮修复

无干扰冷启动复测中，v5 在进入 DSH 后超过 66.8 秒仍显示加载。检查发现 `RestoreSession()` 恢复登录并完成 `DiscoverLanEndpoint(false)` 后，只刷新多媒体和网盘，遗漏 DSH。若首次进入发生在认证恢复前，首次连接直接返回；若端点发生切换，既有连接及加载监测会被取消。两种情况都缺少后续启动。

v6 在登录恢复和端点发现完成后，检查账号版本是否仍有效，并在当前页为 DSH 时调用既有重连流程。认证策略、票据来源和 60 秒截止时间保持原有实现。本次源码仅修改 `Index.ets` 的这一恢复分支，并扩展对应回归检查；工作区其他改动不属于本轮。

## 验证结果

| 检查 | 结果 |
| --- | --- |
| HAP 签名、覆盖安装、冷启动、进程 | 通过。 |
| 冷启动恢复的回归 | 真实 `RestoreSession`、`ApplyBusinessEndpoint`、`ConnectDshWeb` 方法通过模拟异步顺序测试；临时移除本次修复后，同一测试如预期失败：只发起一次连接，没有恢复被取消的连接。工作区源文件未因对照测试修改。 |
| 启动前提前进入 DSH | 认证恢复后开始连接；账号版本改变后的迟到恢复不会发起连接。 |
| DSH 认证、弹窗、下载、端点路由检查 | 通过；端点路由共 37 项。 |
| ArkTS 构建 | 成功。存在已有 `DownloadToolsPage.ets:79` 的 `READ_PASTEBOARD` 权限声明警告，本轮未修改该模块。 |
| 额外认证静态检查 | 未通过已有 `LoginPage` 的固定连接重试 accessibility 文案断言；本轮没有修改 `LoginPage`，未将该脚本计为通过。 |
| 真机启动后立即进入 DSH | 约 21.5 秒后显示网络错误及重连按钮，不再无限加载。 |
| 第一次手动重连 | 约 21.5 秒后网络错误，保留重连入口。 |
| 第二次手动重连 | 观察到网页加载，约 61.2 秒采样时显示“DSH 加载超过 60 秒”，加载指示已结束，重连按钮可见。 |
| 服务健康 | 通过当前配置的直接 SSH 连接，只读检查网关 `/actuator/health` 返回 200。 |

因此不能把本轮结果表述为“DSH 所有功能正常”。v5 曾在同一真机打开首页、工作区、历史列表及通用设置，但模型/插件异步内容不全，实时连接也出现重试。v6 本轮未能稳定进入这些页面，不能将 v5 或模拟器证据当作 v6 的完整交互通过结果。
