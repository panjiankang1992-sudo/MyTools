# 教材保存发布冲突修复 — 2026-10-18

## 已确认原因

生产只读核验：英语四上教材 `en-yl-4-1-yilin-2024` 的当前发布版本为 `1.0.5`，编辑草稿仍基于 `1.0.3`，草稿修订为 4、159 条。刷新只会重新读取这份已保存的旧基线草稿。后端因此返回 `baselineMismatch`，前端原先把所有 409 误报为“其他人更新”。这不构成有第二个用户编辑的证据。

导入新教材会推进发布指针，但不会覆盖已有草稿。因此需要三方合并，不能只替换基线版本号。另有旧数据版本重新编号，按 entryId 直接套用修改会影响错误单词。

## 修复行为

1. 保存草稿后发布遇到基线过期时，自动请求一次安全同步，再使用返回的完整草稿、新修订号和新基线发布。
2. 后端比较旧版不可变教材、最新不可变教材和已保存草稿，保留不冲突的手工修改、最新教材内容、来源与目录关系。
3. 历史编号复用须通过同单元、同课文和完整文本的唯一对应定位；歧义或真实同字段冲突停止，不覆盖输入。中文释义仅末尾一个句号的差异允许识别为同一新增项，并保留用户字面内容。
4. 同步接口要求管理员权限、CSRF、If-Match 和幂等键；事务内锁定教材并核对修订及版本指针。网络不确定重试沿用同一请求标识。
5. 409 按实际原因提示，不再统一归因于其他人操作。读取草稿的 GET 不修改数据。
